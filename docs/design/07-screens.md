# 07. 화면 설계

> 🚧 미작성. 작성할 항목과 이미 정해진 관련 결정만 적어 둔다.

## 작성할 항목

- 화면 목록과 화면 전환 (PRD 4장이 설계 문서로 미룬 세부 화면·문구, U-15)
- 화면별 구성요소와 Loading / Empty / Error 상태, 표시 문구
- 분석 상태 표시 (상태 목록은 04장)
  - 대기 중 (앞에 N건)
  - 1단계 분석 중 (입력 가능): 1단계가 끝나기 전에도 차량·파손 부위를 입력할 수 있다 (D-15)
  - 입력 완료·1단계 진행 중, 2단계 분석 중, 확인 가능, 실패
  - GPU EC2를 켜는 중일 때의 대기 안내 (부팅 1~2분)
- 상태 조회 주기 (5~10초, U-18). 너무 자주 묻지 않는다 (D-19)
- 업로드 링크 발급 화면 (피해자용): 링크 발급, 유효 시간 안내, 재발급 (D-28)
- 관리자 업로드 화면: **로그인 없이 링크 주소로 여는 화면**이다 (D-28). 브라우저에서 S3로 직접 업로드, 진행률 표시, 업로드 완료 알림 (D-18). 5GB를 넘는 파일은 업로드 전에 막고 안내 문구를 보여준다 (D-22). 만료·사용 완료된 링크의 안내 문구도 정한다
- 차량 선택·파손 부위 입력 화면 (D-29, 상태 "확정 필요" — 팀장 확인 후 확정). 아래는 입력 방식에서 따라오는 요구사항이고, **화면 구성과 문구는 팀원 1이 U-15에서 정한다**
  - 정지 장면 위에서 **본인 차량 자리를 드래그**한다. 드래그를 놓으면 맞춰진 차량 영역(누끼)이 확정되어 표시된다
  - 확정된 차량 위에서 **한 번 더 드래그해 파손 부위**를 그린다. 차량 영역 밖으로 그렸을 때의 안내 문구를 정한다
  - 맞는 탐지가 없어 드래그한 사각형을 그대로 쓸 때(폴백) 사용자에게 알릴지 🚧
  - 다시 그리기(취소), 5분 이전 이동, 본인 차량이 없을 때의 재업로드 안내
- 후보 확인 화면: 후보 영상, 찾음 / 못 찾음, 남은 후보 수
- 사건 지점 고정 화면: 원본 시간 위치 강조, 고정 전 확인, 고정 해제
- 와이어프레임
- PRD 4장 ⚠️ UX 항목 확정 (고정 전 확인, 키보드 조작, 사건 지점 해제 등)
