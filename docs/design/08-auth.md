# 08. 인증·권한

> 🚧 미작성. 작성할 항목과 이미 정해진 관련 결정만 적어 둔다.

## 작성할 항목

- 업로드 전용 일회용 링크: 발급 API, 토큰 생성 방법, 만료·재발급 처리, 링크로만 할 수 있는 일의 범위 (방식은 D-28로 정리했고 상태는 "확정 필요"다. 세부는 여기서 정한다)
- 로그인 방식: **`sessions` 테이블 + HttpOnly 쿠키 (D-30, 상태 "확정 필요").** 계정은 피해자 것 한 종류뿐이다 (D-28). 여기서 정할 세부는 아래 셋이다
  - 비밀번호 해시 방식 (bcrypt 등)과 `token` 생성 방법
  - 쿠키 속성: `HttpOnly`는 켠다. `Secure`는 HTTPS를 쓰지 않으므로 켜지 않는다 (D-31). `SameSite` 값은 🚧
  - 만료·로그아웃 처리: 로그아웃 = 행 삭제, 유효 시간 7일, 연장 없음 (01장 1.6)
- 원본 접근 차단 방법: API 규칙 + 백엔드 IAM 역할에 원본 영역 읽기 권한을 주지 않음 ([02장 2.9](02-architecture.md#29-aws-서비스와-권한))
- presigned URL 유효 시간 (업로드용, 재생용)
- 다운로드 기능을 제공하지 않는 방법

## 관련 결정·조건

- 로그인 세션은 DB 테이블 + HttpOnly 쿠키: D-30. 테이블은 [04장 `sessions`](04-data-model.md#sessions)
- 관리자는 계정 없이 업로드 전용 일회용 링크로 올린다: D-28. 테이블은 [04장 `upload_tokens`](04-data-model.md#upload_tokens)
- 프론트와 API는 같은 출처: D-11
- 무상태 API 규칙: D-19
- HTTPS를 적용하지 않는다: D-31. 한계는 [02장 2.11](02-architecture.md#211-한계와-알려진-제약)
- 불변 조건 1·8: [02장 2.4](02-architecture.md#24-이중-경로와-불변-조건)
