# 08. 인증·권한

> 🚧 미작성. 작성할 항목과 이미 정해진 관련 결정만 적어 둔다.

## 작성할 항목

- 업로드 전용 일회용 링크: 발급 API, 토큰 생성 방법, 만료·재발급 처리, 링크로만 할 수 있는 일의 범위 (방식은 D-28로 정했다(확정). 세부는 여기서 정한다)
- 계정 만들기: 회원가입은 두지 않는다. 계정은 서버에서 스크립트로 미리 만들고, 데모는 공용 계정 하나를 쓴다. 비밀번호는 실행 중에 입력받는다 (D-44)
- 로그인·로그아웃·내 정보 API와 쿠키 이름(`sid`): [05장 5.3](05-api.md#53-계정-api)
- 로그인 방식: **`sessions` 테이블 + HttpOnly 쿠키 (D-30, 확정).** 계정은 피해자 것 한 종류뿐이다 (D-28). 여기서 정할 세부는 아래 셋이다
  - 비밀번호 해시 방식 (bcrypt 등)과 `token` 생성 방법. 계정 생성 스크립트와 로그인 API가 같은 해시 코드를 쓴다 (D-44)
  - 쿠키 속성: `HttpOnly`는 켠다. `Secure`는 HTTPS를 쓰지 않으므로 켜지 않는다 (D-31). `SameSite` 값은 🚧
  - 만료·로그아웃 처리: 로그아웃 = 행 삭제, 유효 시간 7일, 연장 없음 (01장 1.6)
- 남의 영상 접근 차단: `/api/videos/{video_id}/...`마다 주인을 확인하고, 남의 영상은 404로 답한다 (D-39, [05장 5.1](05-api.md#51-공통-규칙))
- 원본 접근 차단 방법: API 규칙 + 백엔드 IAM 역할에 원본 영역 읽기 권한을 주지 않음 ([02장 2.9](02-architecture.md#29-aws-서비스와-권한))
- presigned URL 유효 시간: 업로드용·재생용 모두 15분, 재생 URL은 조회할 때마다 새로 발급 (D-41, [05장 5.1](05-api.md#51-공통-규칙))
- 다운로드 기능을 제공하지 않는 방법
- **열람 기록 남기기**: 정지 장면 조회, 클립 재생 URL 발급, 사건 고정, 로그인, 업로드 링크 발급 때 `access_logs`에 한 행씩 남긴다 (D-53, [04장 `access_logs`](04-data-model.md#access_logs)). 표준 개인정보 보호지침 제44조⑤가 요구하는 법정 기록이므로 **끄거나 건너뛸 수 있게 만들지 않는다**
- **본인 확인은 하지 않는다**: 표준지침 제44조③은 열람 요구자의 신분증명서 확인을 요구하지만, 데모는 공용 계정(D-44)으로 대신하고 [02장 2.11](02-architecture.md#211-한계와-알려진-제약)에 한계로 적었다. 여기서는 "왜 뺐는지"만 적고 구현하지 않는다

## 관련 결정·조건

- 회원가입 없음, 계정은 스크립트로: D-44
- 로그인 세션은 DB 테이블 + HttpOnly 쿠키: D-30. 테이블은 [04장 `sessions`](04-data-model.md#sessions)
- 관리자는 계정 없이 업로드 전용 일회용 링크로 올린다: D-28. 테이블은 [04장 `upload_tokens`](04-data-model.md#upload_tokens)
- 프론트와 API는 같은 출처: D-11
- 무상태 API 규칙: D-19
- HTTPS를 적용하지 않는다: D-31. 한계는 [02장 2.11](02-architecture.md#211-한계와-알려진-제약). ⚠️ 비밀번호 평문 전송은 고시 제7조① 미이행이다. 알고 뺀 것이며 이유는 D-31에 있다
- 열람·발급·파기 기록: D-53
- S3 버킷은 HTTP 접근을 거부한다: D-55. presigned URL을 `http://`로 바꿔도 S3가 막는다. 다만 URL 문자열이 평문으로 전달되는 것은 못 막는다 (D-31)
- 불변 조건 1·8: [02장 2.4](02-architecture.md#24-이중-경로와-불변-조건)
