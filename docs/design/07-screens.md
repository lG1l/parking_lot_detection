## 1. 화면 목록과 화면 전환

| 화면 | 누가 | 여는 조건 | 이 장 |
|---|---|---|---|
| 로그인 | 피해자 | 3번이 401 | 2.1 |
| 영상 목록 | 피해자 | 로그인 뒤 첫 화면 | 2.2 |
| 업로드 링크 발급 | 피해자 | 목록의 [업로드 링크 받기] | 2.3 |
| 관리자 업로드 | 관리자 (로그인 없음) | 링크 주소 `/#/upload/{token}` | 2.4 |
| 영상 상태 (대기 안내) | 피해자 | 목록에서 영상을 누름 | 2.5 |
| 차량·파손 부위 입력 | 피해자 | `stage1_done`이고 `input_done`이 `false` | 2.6 |
| 후보 확인 | 피해자 | `ready`·`batch_running` | 2.7 |
| 완료 | 피해자 | `exhausted` | 2.8 |
| 결과 (고정 목록) | 피해자 | `finished`, 또는 `exhausted`인데 고정이 1개 이상 | 2.9 |
| 보관 기간 종료 | 피해자 | `masked_deleted`가 `true` | 2.10 |

- **주요 흐름(피해자용)**: 로그인 ➔ 영상 목록 ➔ 업로드 링크 발급 ➔ (관리자가 업로드) ➔ 영상 상태(대기) ➔ 차량·파손 부위 입력 ➔ 영상 상태(분석 중) ➔ 후보 확인(여러 번 [찾음]) ➔ 결과 화면(또는 완료 화면)
- **업로드 흐름(관리자용)**: 업로드 링크 주소로 접속 ➔ 관리자 업로드 화면 ➔ 업로드 완료 알림
- **영상 목록은 언제든 돌아올 수 있는 중심 화면이다 (D-110, D-111).** 한 영상의 확인을 끝내지 않아도 목록으로 돌아가 다른 영상을 열거나 새 업로드 링크를 받을 수 있다. 화면을 떠나는 것은 확인을 미루는 것일 뿐이며 분석은 계속된다 (3.7).
- 사건 지점은 따로 고정하는 화면이 없다. **후보 확인 화면의 [찾음]으로 고정**하고, 고정한 것은 결과 화면에서 모아 본다 (D-80).
- 영상 상태 화면은 9번 응답으로 어느 화면을 보일지 고른다. 순서는 **`masked_deleted` → `status` → (`stage1_done`이면) `input_done` → (`exhausted`면) `candidate_total`** 이다 ([05장 5.11 "9번 응답으로 화면 고르기"](05-api.md#9번-응답으로-화면-고르기)).

## 2. 화면별 세부 명세 및 구성 요소

### 2.1 로그인 화면
- **구성**: 아이디, 비밀번호 입력란, [로그인] 버튼.
- 회원가입 화면은 제공하지 않으며, 사전에 만들어 둔 계정으로 로그인한다 (D-44).
- 앱이 처음 열릴 때 3번을 불러 200이면 영상 목록으로, 401이면 이 화면으로 온다.
- `LOGIN_FAILED`: "아이디 또는 비밀번호가 올바르지 않습니다." 어느 쪽이 틀렸는지 구분하지 않는다 (05장 1번).

### 2.2 영상 목록 화면 (피해자용)
- **구성**: [업로드 링크 받기] 버튼, 내 영상 목록(파일 이름, 상태, 열람기한), [새로고침] 버튼, [로그아웃].
- **동작**:
  - 화면을 열 때와 [새로고침]을 누를 때만 8번을 부른다. 주기적으로 부르지 않는다 **(팀원 1 안)**. 상태가 바뀌는 것은 영상 상태 화면이 9번으로 본다 (D-19).
  - 목록의 상태는 아래 "상태 짧은 이름"으로 보인다. "앞에 N건"은 목록에 없다 (05장 8번).
  - 열람기한은 `view_expires_at`을 3.3 형식("YYYY-MM-DD HH:mm까지 열람 가능")으로 보인다. `null`이면 "업로드 완료 후 열람기한이 정해집니다" (D-92, 3.3). 기한은 영상마다 따로이고, 다른 영상을 올리거나 확인을 미뤄도 늘어나지 않는다 (D-110).
  - **[업로드 링크 받기]는 늘 누를 수 있다.** 확인이 끝나지 않은 영상이 있어도 막지 않는다 (D-110).
  - 영상을 누르면 끝났든 아니든 영상 상태 화면(2.5)으로 들어가 이어서 본다. 저장된 입력·확인 진행·고정은 영상별로 남아 있다 (D-110, D-111).
  - 목록 위 안내 **(팀원 1 안)**: "확인을 끝내지 않은 영상도 목록에서 다시 열어 이어서 볼 수 있습니다. 영상마다 열람기한이 다릅니다."
- **상태 짧은 이름 (팀원 1 안)**:

| `status` | 목록에 보일 이름 |
|---|---|
| `uploading` | 업로드 중 |
| `upload_failed` | 업로드 확인 안 됨 |
| `queued` | 대기 중 |
| `stills_running` | 준비 중 |
| `stage1_done` | 입력 필요 (입력 뒤에도 같은 이름. 목록에는 `input_done`이 없다) |
| `stage2_running` | 분석 중 |
| `ready`·`batch_running` | 확인 가능 |
| `finished` | 확인 끝남 |
| `exhausted` | 후보 확인 완료 |
| `failed` | 분석 실패 |

### 2.3 업로드 링크 발급 화면 (피해자용)
- **구성**: [링크 발급] 버튼, 발급된 링크 주소와 [주소 복사] 버튼, 유효 시간 안내(`expires_at`), 재발급 버튼.
- **동작**:
  - 발급 API(4번)는 버튼을 눌렀을 때만 호출한다. 화면을 열거나 새로 고칠 때 부르면 이미 관리자에게 보낸 링크가 무효가 된다 (05장 5.4).
  - 링크 주소는 4번이 준 `token`에 지금 열린 주소를 앞에 붙여 프론트가 만든다: `http://<지금 주소>/#/upload/{token}` (D-12).
  - 다시 발급하면 이전 링크가 무효화된다는 것을 버튼 옆에 안내한다 (05장 5.4).
  - 피해자가 원본 영상을 직접 올리는 경로는 없다 (D-45).
- **안내 문구**:
  - "이 링크는 주차장 관리자에게 보여주는 용도입니다."
  - "링크는 YYYY-MM-DD HH:mm까지 한 번만 쓸 수 있습니다." (`expires_at`)
  - 재발급 버튼 옆: "다시 발급하면 이전 링크는 쓸 수 없게 됩니다."

### 2.4 관리자 업로드 화면
- **구성**: 별도 로그인 없이 피해자가 전달한 링크 주소로 접속하는 화면 (D-28). 파일 선택 버튼, **녹화 시작 시각 입력란(선택)**, [업로드] 버튼, 진행률 표시바, 완료 알림 (D-18, D-85).
- **안내 문구 (화면 위)**: "차가 이미 주차된 뒤의 장면부터 영상을 잘라서 올려 주세요. 녹화기의 MP4·AVI 내보내기를 쓰면 됩니다." (D-43, D-65 — 첫 장면에 피해 차량이 보여야 한다)
- **동작**:
  - 화면을 열자마자 5번으로 링크를 쓸 수 있는지 확인한다. 쓸 수 없으면 파일 선택을 보이지 않고 안내만 보인다.
  - 파일을 고르면 확장자와 크기를 **업로드 전에** 막는다 (D-22, D-43).
  - 녹화 시작 시각은 "영상 첫 장면의 실제 날짜·시각"이다. 모르면 비워 둔다. 지금보다 뒤의 시각은 막는다 (D-85, 05장 6번).
  - [업로드]를 누르면 6번을 부르고 **버튼을 바로 막는다.** 받은 `upload_url`로 브라우저에서 S3로 직접 `PUT`한다. 본문에 파일 바이트를 그대로 싣고 `If-None-Match: *` 헤더를 붙인다 (05장 6번, D-100). 파일을 메모리에 통째로 올리지 않고 파일 객체를 그대로 넘긴다.
  - 진행률은 `XMLHttpRequest`의 `progress` 이벤트로 얻는다 (`fetch`·`package:http`의 `put`으로는 진행률이 나오지 않는다).
  - 같은 진행 이벤트로 남은 시간 = (전체 − 올린 크기) ÷ 현재 속도를 계산해, **임계(01장 1.6, 3분) 이하가 되는 순간 16번을 1회** 부른다. 실패해도 무시한다 (D-62).
  - S3가 `200`을 주면 7번을 부르고 완료 알림을 보인다. 7번이 500이면 같은 요청을 다시 보낸다 (두 번 불러도 된다, 05장 7번).
- **에러 및 상태 문구**:
  - 5GB 초과 파일 선택 시 (D-22): "파일 용량이 5GB를 초과하였습니다"
  - 미지원 확장자 선택 시 (D-43): ".mp4, .avi, .mkv, .mov인 확장자만 선택해주세요. 녹화기의 MP4·AVI 내보내기를 써 주세요."
  - `UPLOAD_TOKEN_NOT_FOUND`: "링크 주소가 올바르지 않습니다. 주소를 다시 확인해 주세요."
  - `UPLOAD_TOKEN_USED`·`UPLOAD_TOKEN_EXPIRED`: "만료되거나 이미 사용이 완료된 링크입니다. 피해자에게 새 링크를 받아 주세요."
  - S3가 `412`·`409`를 주면 (D-100): "업로드가 거절됐습니다. 피해자에게 새 링크를 받으세요." 7번은 부르지 않는다.
  - S3가 `403`을 주면: "업로드할 수 없습니다. 피해자에게 새 링크를 받아 주세요." 7번은 부르지 않는다. `If-None-Match` 헤더를 빠뜨린 버그일 수 있으므로 개발 중에는 콘솔에 상태 코드를 남긴다 (D-100).
  - S3 응답별 처리 요약: `200` → 7번 호출 / `412`·`409` → 거절 안내 / `403` → 위 안내 / 그 밖·네트워크 오류 → 아래 "업로드 도중 끊김" 안내.
  - 업로드 도중 끊김(네트워크 오류): "업로드가 중단됐습니다. 이 링크는 다시 쓸 수 없으니 피해자에게 새 링크를 받아 주세요." (링크는 6번에서 쓴 것이 된다, 05장 6번)
  - 완료: "업로드가 끝났습니다. 이 창을 닫아도 됩니다."
- "업로드 중"·"업로드 확인 안 됨" 문구는 이 화면이 아니라 피해자의 영상 상태 화면(2.5)에 있다 (D-47).

### 2.5 영상 상태 화면 (공통 대기)
- **구성**: 상태 안내 문구, [목록으로] 버튼 (D-110, 3.7).
- **동작**:
  - 9번을 5초마다 부른다 (D-138, D-19).
  - **주기 조회를 멈추는 때 (팀원 1 안)**: 끝 상태(`finished`·`exhausted`·`failed`), `ready`(사용자가 움직여야만 바뀐다), `masked_deleted`가 `true`일 때. `batch_running`에서는 `ready`가 될 때까지 계속 부른다. [분석 다시 시도]가 접수되면 다시 부르기 시작한다 (아래 "실패 안내").
  - 화면을 떠나면 조회를 멈춘다. 떠나도 분석은 계속된다 (D-111).
- **상태별 안내 문구** (9번 응답으로 고른다):

| 조건 | 화면 | 문구 |
|---|---|---|
| `masked_deleted` = `true` | 보관 기간 종료 (2.10) | |
| `uploading` | 대기 | "관리자가 영상을 업로드 중이므로 아직 열 수 없습니다." (D-47) |
| `upload_failed` | 대기 | "업로드가 확인되지 않습니다 — 큰 파일이면 아직 올라오는 중일 수 있습니다. 한참 지나도 그대로면 관리자에게 확인하고, 중단됐다면 링크를 다시 발급하세요." **실패로 단정하지 않는다** (D-47) |
| `queued` | 대기 | "처리를 대기중입니다. 앞에 N건이 있습니다." (`queue_ahead`, D-19). GPU가 꺼져 있을 수 있으므로 "서버를 켜는 데 1~2분이 더 걸릴 수 있습니다."를 함께 보인다 |
| `stills_running` | 대기 | "차량을 고를 장면을 준비하고 있습니다. 수십 초 걸립니다." |
| `stage1_done`, `input_done` = `false` | 입력 화면 (2.6)으로 바로 간다 | |
| `stage1_done`, `input_done` = `true` | 대기 | "입력을 저장했습니다. 분석 차례를 기다리는 중입니다. 앞에 N건이 있습니다." + 아래 "나중에 다시" 문구 |
| `stage2_running` | 대기 | "영상을 분석하고 있습니다. 24시간 영상이면 약 30분 걸립니다." + 아래 "나중에 다시" 문구 |
| `ready`·`batch_running` | 후보 확인 (2.7) | |
| `finished` | 결과 (2.9) | |
| `exhausted` | 완료 (2.8), 고정이 있으면 결과 (2.9) | |
| `failed` | 실패 안내 | 서버가 알려 주는 실패 종류로 문구를 고른다. 아래 "실패 안내" (D-112) |

- **"나중에 다시" 문구**: "이 창을 닫고 나중에 다시 접속해도 됩니다. 분석은 계속 진행됩니다." (D-67, 02장)
- `queued`의 "앞에 N건"에는 내가 먼저 올린 다른 영상도 들어갈 수 있다. GPU 1대가 하나씩 처리하므로 여러 영상을 올리면 뒤 영상은 더 기다린다. 이 대기는 데모의 알려진 한계다 (D-111).

#### 실패 안내 (`failed`, D-112)
실패 종류, 재시도 가능 여부, 남은 재시도 횟수는 **서버가 9번 응답으로 알려 준다.** 화면은 실패 이유를 짐작하지 않고, 개발자용 오류 원문(`error_message`)도 보이지 않는다. 필드 이름은 05장 9번에 아직 없다 ⚠️ (👤 팀원 2, D-112 "담당자 상세 반영").

| 서버가 알려 준 경우 | 문구 | 버튼 |
|---|---|---|
| 일시적인 서비스 오류, 재시도 가능 | "일시적인 서비스 문제로 분석을 완료하지 못했습니다. 다시 시도해 주세요. 문제가 계속되면 운영 담당자에게 문의해 주세요." | [분석 다시 시도] |

| 서비스 오류, 재시도 3회를 모두 씀 | "재시도 가능 횟수(3회)를 모두 사용했습니다. 운영 담당자에게 문의해 주세요." | 없음 |
| 서비스 오류, 그 밖에 재시도 불가 | "서비스 문제로 분석을 완료하지 못했습니다. 운영 담당자에게 문의해 주세요." **(팀원 1 안)** | 없음 |
| 파일 문제 (손상, 지원하지 않는 코덱, 길이 0 등) | "영상 파일에 문제가 있어 분석할 수 없습니다. 관리자에게 영상 파일을 확인한 뒤 새 업로드 링크로 다시 올려 달라고 요청하세요." | [업로드 링크 받기] (2.3) |
| 기한 만료·원본 파기 | 보관 기간 종료 화면(2.10)과 같은 안내 | 없음 |

- **[분석 다시 시도]** (D-112):
  - 누르는 즉시 버튼을 막고 "다시 시도를 요청하는 중입니다."를 보인다. 확인창은 띄우지 않는다 **(팀원 1 안)** — 되돌릴 것이 없고, 서버가 중복 요청을 한 번만 접수한다.
  - 버튼 아래에 서버가 준 남은 횟수를 보인다: "다시 시도 가능: N회 남음". 화면에서 세지 않는다. 다시 접속해도 서버 값으로 그린다.
  - 접수되면 9번을 다시 부르고 주기 조회를 시작한다. 그러면 실패한 단계에 맞는 대기 화면(`queued`·`stills_running`·`stage2_running`·`batch_running`)이 나온다. 이미 저장한 입력, 받은 후보, 고정, 확인 진행은 그대로 있다.
  - 거절되면(이미 접수됨, 상태가 바뀜, 기한 지남, 횟수 소진 등) 3.1대로 9번을 다시 불러 그 응답으로 화면을 새로 그린다. 횟수 소진이면 위 표의 문의 안내가 나온다.
  - 부르는 API는 05장에 아직 없다 ⚠️ (👤 팀원 2, D-112). 3.1의 "보내는 즉시 버튼을 막는 API"에 넣는다.
- 3번째 재시도가 진행 중이면 대기 화면을 그대로 보인다. 성공하면 평소처럼 다음 화면으로 간다.
- 2단계 진행률이나 남은 예상 시간은 보이지 않는다. "약 30분"만 안내한다 **(팀원 1 안)**. 그래서 9번에 진행률 키를 더할 필요가 없다 (05장 5.10, D-67).
- `duration_sec`가 `null`이면 영상 길이를 보이지 않는다.
- 끝 상태가 아니면 열람기한(`view_expires_at`)을 화면 아래에 작게 보인다 (3.3).

### 2.6 차량 선택·파손 부위 입력 화면 (피해자용)
- **구성**: 영상 시작 정지 장면 1장(다른 시점 이동 없음, D-48), 탐지된 차량들의 사각형 겹쳐서 표시, 단계 안내 문구, [이전 단계] 버튼, **파손 사진 1장(선택)과 텍스트 설명(선택)** 입력란 (D-72).
- 화면을 열 때 10번을 한 번 부른다. 좌표는 모두 **원본 해상도 기준 픽셀 정수**로 보낸다. 이미지를 축소해 보여주므로 `naturalWidth`·`naturalHeight`로 표시 배율과 여백을 빼 되돌린다 (05장 5.6·5.7).
- 단계 사이에는 서버를 부르지 않는다. 마지막 확인창의 [저장]에서만 부른다 (D-36).
- **[목록으로]**: 저장하지 않은 입력은 남지 않는다 (D-111, 자동 저장 없음). 무엇이든 입력했으면 확인창 "저장하지 않은 입력은 사라집니다. 목록으로 갈까요?" [목록으로] / [계속 입력]을 띄운다 **(팀원 1 안)**. 다시 들어오면 ①부터 입력한다.
- **단계 (순서는 팀원 1 안, D-98)**:
  - **① 차량 고르기** — "본인 차량을 눌러 선택해주세요"
    - `detections`의 사각형 중 본인 차량 하나를 눌러 고른다. 차량을 별도로 드래그하지 않는다 (D-65).
    - 고른 사각형은 다른 색·굵기로 강조하며, 고르기 전에는 넘어갈 수 없다.
    - **겹친 사각형 (팀원 1 안)**: 누른 점을 품는 사각형이 여럿이면 **넓이가 가장 작은 것**을 잡는다. 앞에 있어 덜 가려진 차일 가능성이 크다. 다시 누르면 그다음으로 작은 것으로 바뀐다.
    - **많을 때 표시 (팀원 1 안)**: 고르기 전 사각형은 얇은 선(2px)만 그리고 채우지 않는다. 마우스를 올린 사각형만 굵게 보인다.
    - **[내 차가 목록에 없습니다]** 버튼을 둔다. 누르거나 `detections`가 빈 배열이면 재업로드 안내로 간다 (아래, D-65).
  - **② 탐지 상황 고르기** — "파손 부위가 이 장면에 보이나요?" [보임] / [안 보임] (D-72). ①은 두 경우 모두 한다.
  - **③ 파손 부위 사각형 드래그**
    - [보임]: "파손 부위를 드래그해주세요". **고른 차량 사각형 안에서만** 받는다. 밖으로 그리면 "파손 부위가 차량을 벗어났습니다. 다시 그려주세요." (D-65, D-92)
    - [안 보임]: "보이지 않는 파손이 있을 위치를 작은 사각형으로 드래그해주세요". **원본 화면 어디든** 받는다. 차량 밖도 된다 (D-92, U-25 해결).
  - **④ 내 차 바닥 네 모서리 찍기** — "내 차 바퀴 아래, 차가 바닥에 닿는 네 모서리를 차 둘레를 따라 차례로 눌러주세요. 가려진 모서리는 짐작해서 찍어도 됩니다." (D-98)
    - 찍은 점에 1~4 번호를 붙이고, 4개를 찍으면 찍은 순서대로 이어 사각형을 그린다.
    - 마주 보는 변이 서로 만나면(꼬인 사각형) "모서리를 차 둘레를 따라 차례로 찍어주세요."를 보이고 다시 찍게 한다. 같은 점을 두 번 찍지 못하게 한다 (05장 5.7 검증 11·12).
    - [다시 찍기]로 네 점을 지운다.
  - **⑤ 파손 변 고르기** — "파손이 있는 쪽 변을 눌러주세요. 모서리 파손이면 이웃한 두 변을 누르세요." (D-98)
    - ④의 네 변을 누를 수 있는 선으로 보인다. 1개, 또는 **이웃한** 2개만 고를 수 있다. 마주 보는 변을 누르면 "이웃한 두 변만 고를 수 있습니다."를 보인다 (05장 5.7 검증 13).
    - 변 번호는 찍은 순서로 정한다: 변 i = 점 i → 점 (i+1) % 4 (`damage_edges`).
  - **⑥ 사진·설명 (선택)** — "파손 사진과 설명이 있으면 분석에 도움이 됩니다. 없어도 저장할 수 있습니다."
    - 사진은 1장, 20MB, `.jpg` `.jpeg` `.png` `.heic`만 받는다. 고르는 즉시 막는다 (D-83). 미리보기는 고른 로컬 파일이다 (D-92).
    - 설명은 500자까지 받는다. 글자 수를 보인다.
  - **⑦ 확인창** — 고른 차량, 파손 부위, 바닥 네 모서리, 고른 파손 변을 정지 장면 위에 함께 그리고, 탐지 상황·사진·설명을 함께 보여준다.
    - 문구: "이대로 분석을 시작합니다. 저장한 뒤에는 고칠 수 없습니다." [저장] / [취소]
    - [취소]하면 ①로 돌아간다. 이미 입력한 값은 남겨 두고 단계마다 [이전 단계]로 고칠 수 있다.
- **저장 처리**:
  - 사진이 있으면 18번으로 URL을 받아 S3에 `PUT`(본문에 바이트 그대로)한 뒤 받은 `photo_key`를 11번에 담는다 (D-83).
  - **사진 올리기가 실패하면** "사진을 올리지 못했습니다." [다시 올리기] / [사진 없이 저장]을 보인다. 올리지 못한 사진의 키는 11번에 담지 않는다 (D-92). 이 창은 **S3 PUT 실패나 네트워크 오류일 때만** 띄운다.
  - 18번이 409 `RAW_EXPIRED`(기한 지남)나 `INVALID_STATE`를 주면 위 창을 띄우지 않고 3.1대로 9번을 다시 불러 화면을 새로 그린다. `RAW_EXPIRED`면 보관 기간 종료 화면(2.10)이 나온다 (D-102). 11번이 `RAW_EXPIRED`를 줄 때도 같다.
  - [저장] 시 11번을 1회 부르고 **버튼을 바로 막는다.** [다시 입력] 버튼은 제공하지 않는다 (D-66).
  - 성공하면 응답의 `status`·`input_done`으로 영상 상태 화면(2.5, 2단계 대기)을 그린다.
  - 상태 조회의 `input_done`이 `true`면 입력 화면을 열지 않는다. 409 `INVALID_STATE` 발생 시 상태를 다시 조회해 화면을 새로 그린다.
- **재업로드 안내** (탐지 0건, [내 차가 목록에 없습니다]) (D-65, PRD 3.2):
  - "이 장면에서 본인 차량을 찾지 못했습니다. 관리자에게 차가 이미 주차된 뒤의 장면부터 영상을 다시 잘라 달라고 요청한 뒤, 새 업로드 링크를 발급해 전달해 주세요." [업로드 링크 받기]로 2.3에 간다.
  - 가려졌든 아직 들어오지 않았든 안내는 이 하나다. 이 영상의 입력은 저장하지 않는다.

### 2.7 후보 확인 화면
- **구성**:
  - 탭 2개: **[후보]**(`main`) / **[점수 미산출]**(`parse_failed`) (D-93). 탭 이름은 **(팀원 1 안)**.
  - 본인 차량 주변으로 잘라낸 후보 클립 목록(묶음 최대 10개, D-70). 후보마다 비디오 플레이어와 [찾음] 버튼.
  - 묶음 아래: [◀ 이전] · "묶음 2 / 3" · [다음 ▶] (D-79). 남은 후보 수(`remaining`) 표시 (D-37).
  - 고정이 1개 이상이면 [확인 끝내기] (D-80).
  - [나중에 확인] — 목록으로 간다 (D-110, 3.7).
  - 열람기한 "이 결과는 YYYY-MM-DD HH:mm까지 열람 가능합니다." (`view_expires_at`, 3.3)
- **열 때**: 12번(`list=main`)과 15번("확정됨" 표시용)을 부른다.
- **비디오 플레이어**: 클립은 본인 차량 주변을 크롭한 영상이다. 가로·세로 비율을 지키고 남는 곳은 검은 여백으로 채운다(`BoxFit.contain`). 진행바 위에 사건 지점(`incident_at_sec − start_sec`)을 빨간 눈금으로 표시한다 **(팀원 1 안)**. 크롭 영역(`crop_bbox`)을 전체 화면 위에 보이지는 않는다 **(팀원 1 안)** — 12번에 키를 더할 필요가 없다 (05장 5.10).
- **동작**:
  - VLM 점수는 화면에 노출하지 않으며 배열 순서대로 보여준다 (05장 5.8).
  - **[찾음]**: 확인창 "이 장면을 사건 지점으로 고정합니다. 고정은 취소할 수 없습니다." [고정] / [취소] (D-40). [고정]이면 14번을 부른다. 화면을 떠나지 않는다. 응답(= 고정 목록)으로 고정한 후보에 **"확정됨"** 표시를 붙이고 그 [찾음]은 막는다 (D-80). 여러 장면을 고정할 수 있다.
  - **[◀ 이전]·[다음 ▶] (이미 받은 묶음 사이)**: 12번에 `?list=…&batch_no=N`을 붙여 부른다. 서버 상태는 바뀌지 않는다 (D-79). 첫 묶음에서는 [◀ 이전]을 막는다.
  - **[다음 묶음 받기]**: 보고 있는 묶음이 그 탭의 `latest_batch_no`이고 그 탭의 `done`이 `false`이고 `status`가 `ready`일 때만 [다음 ▶] 자리에 보인다. 13번에 `list`와 `batch_no`를 보낸다. **누르는 즉시 버튼을 막는다** (05장 5.8).
    - 확인창은 **이 탭의 `remaining`이 `0`이고 다른 탭의 `done`이 `true`일 때만** 띄운다: "마지막 묶음입니다. 넘기면 후보 확인이 끝나고 더는 [찾음]을 누를 수 없습니다." [넘기기] / [취소] (D-79, D-99). 다른 탭에 볼 후보가 남았으면 확인창 없이 보낸다.
    - 응답이 `ready`면 12번으로 다음 묶음을 연다. `batch_running`이면 대기 안내를 보이고 9번을 주기적으로 불러 `ready`가 되면 연다. `exhausted`면 완료 또는 결과 화면으로 간다.
  - **다음 묶음을 만드는 동안(`batch_running`)**: 묶음 자리 위에 "다음 영상 묶음을 만드는 중입니다." 띠를 보인다. **이전 묶음을 가리지 않는다** — [◀ 이전]으로 이미 받은 묶음을 보고 [찾음]을 누를 수 있다 (D-79).
  - **[확인 끝내기]**: 확인창 "후보 확인을 끝냅니다. 끝낸 뒤에는 더는 [찾음]을 누를 수 없습니다." [끝내기] / [취소]. 17번을 부르고 결과 화면(2.9)으로 간다 (D-80). 고정이 0개면 버튼이 없고 [다음]으로 후보를 넘겨 완료 화면으로 끝난다. 서버도 고정 0개면 거절한다 (D-110). 거절되면 3.1대로 9번을 다시 불러 그린다.
  - **[나중에 확인]**: 확인창 없이 목록으로 간다. 17번·13번을 부르지 않는다. 보던 묶음, 고정, 넘긴 묶음은 서버에 남아 있다. 버튼 옆 안내 **(팀원 1 안)**: "확인한 내용은 저장되어 있습니다. 열람기한 안에 목록에서 다시 열어 이어서 확인할 수 있습니다." (D-110, D-111)
  - **이어서 들어올 때**: 9번으로 화면을 고른 뒤 12번을 `batch_no` 없이 불러 그 탭의 마지막 묶음을 연다. 그사이 상태가 바뀌었으면(`batch_running`이 `ready`로 등) 그대로 따른다 (D-111). 보던 영상의 재생 위치는 되살리지 않는다.
- **열람 불가 후보 (D-109)**:
  - 클립을 만들지 못한 후보는 목록에 카드로 보이지 않고 수만 알린다. 묶음 위에 "이 묶음에 영상을 준비하지 못해 볼 수 없는 후보가 N건 있습니다." **(팀원 1 안)**. 0건이면 보이지 않는다.
  - 탭 이름 옆 남은 수(`remaining`)에는 열람 불가를 넣지 않는다. 열람 불가는 [찾음]·[다음] 대상이 아니다.
  - 묶음의 후보가 **모두** 열람 불가일 수 있다. 이때 묶음 자리에 "이 묶음의 후보는 모두 영상을 준비하지 못했습니다." **(팀원 1 안)**를 보이고 [다음 묶음 받기]·[◀ 이전]은 평소처럼 둔다. 열람 불가 때문에 기다리거나 같은 묶음을 다시 받지 않는다 (D-109 5).
  - [후보]·[점수 미산출] 두 탭 모두 같다. "점수 미산출"(VLM이 점수를 못 냄)과 "열람 불가"(영상을 못 만듦)는 다른 것이므로 문구를 섞지 않는다.
  - 열람 불가 수의 필드 이름은 05장 12·13번에 아직 없다 ⚠️ (👤 팀원 2, D-109).
- **[점수 미산출] 탭** (D-93, D-99):
  - 탭 위 설명: "AI가 점수를 내지 못한 후보입니다. 사건 가능성이 낮다는 뜻은 아닙니다."
  - 묶음·[찾음]·[다음] 동작은 [후보] 탭과 같다. 탭을 바꿀 때는 12번만 부른다.
  - **비었을 때 (팀원 1 안)**: `lists.parse_failed.latest_batch_no`가 `null`이면 탭은 보이되 누를 수 없게 하고 "(0)"을 붙인다. 12번을 `list=parse_failed`로 부르지 않는다 (부르면 422).
- **한 탭을 다 넘겼을 때 (팀원 1 안)**: 그 탭의 `done`이 `true`이고 다른 탭의 `done`이 `false`면, 묶음 아래에 "이 목록의 후보를 모두 확인했습니다. 다른 탭에 확인할 후보가 남아 있습니다." [다른 탭 보기]를 보인다. 이 탭에 열람 불가가 있었으면 앞 문장을 "이 목록에서 볼 수 있는 후보를 모두 확인했습니다. 열람 불가 N건이 있습니다."로 바꾼다 (D-109). 이전 묶음은 계속 볼 수 있다.
- 각 탭 이름 옆에 남은 후보 수를 보인다: "[후보 20] [점수 미산출 3]" (`lists.*.remaining`).

### 2.8 완료 화면 (`exhausted` 상태)
- `candidate_total > 0`이면 열람 불가 수(D-109)에 따라 문구를 고른다. 고정한 것이 있으면 결과 화면(2.9)을 보인다 (15번이 빈 배열이 아니면).

| 경우 | 문구 |
|---|---|
| 열람 불가 0건 (두 탭의 후보를 전부 넘김) | "모든 후보를 확인했습니다" (PRD 3.6) |
| 일부 열람 불가 | "열람 가능한 후보를 모두 확인했습니다. 열람 불가 N건이 있습니다." (D-109) |
| 전부 열람 불가 | "후보 구간 N건을 찾았지만 영상을 준비하지 못해 볼 수 없습니다. 운영 담당자에게 문의해 주세요." **(팀원 1 안)**. "모두 확인했다"고 쓰지 않는다 (D-109 5) |

- `candidate_total == 0` (애초에 후보 0건): "후보 구간이 탐지되지 않았습니다" (**사건 없음으로 표기 금지**, PRD 3.5, D-50). 후보 확인 화면은 열리지 않는다.
- 열 때 9번과 15번을 부른다 (05장 5.11). 열람 불가 수는 05장이 정할 필드에서 받는다 ⚠️ (👤 팀원 2, D-109).
- [목록으로]를 둔다 (3.7).

### 2.9 결과 화면 (고정한 사건 지점 목록)
- **여는 조건**: `finished`일 때, 그리고 `exhausted`인데 고정이 1개 이상일 때 (D-80). 15번으로 고정 목록을 받는다.
- **구성**: 고정한 순서대로 항목을 나열한다. 항목마다 비식별화된 클립 플레이어, 원본 기준 시간, 추정 실제 시각. 고정 해제 및 다운로드 버튼은 제공하지 않는다 (D-40, 불변 조건 8). 화면 위에 [목록으로] (3.7).
- `exhausted`로 와서 열람 불가가 있었으면 목록 위에 2.8의 "일부 열람 불가" 문구를 함께 보인다 (D-109).
- **관련 문구 및 설정**:
  - **시각적 표시 방식**: 플레이어 진행바에 사건 지점(`incident_at_sec − start_sec`)을 빨간 눈금으로 표시한다. 2.7과 같다.
  - **시간 표시 형식**: API가 주는 초(실수) 단위 시간(`start_sec`·`end_sec`)을 시:분:초 형식(예: `03:40:35 ~ 03:41:05`, 초 미만 버림)으로 바꿔, 경찰에게 바로 전달할 수 있는 '원본 영상 기준 시간'으로 크게 보인다. 라벨: "영상 시작부터".
  - **추정 실제 시각 (D-85)**: `est_start_at`·`est_end_at`이 있으면 경과 시간 옆에 "2026-09-17 03:40:35 ~ 03:41:05 (관리자 입력 기준 추정)"으로 보인다. `null`이면 이 줄을 보이지 않는다. 경과 시간은 늘 함께 보인다.
  - **기한 안내 문구**: 화면 상단에 "이 결과는 YYYY-MM-DD HH:mm까지 열람 가능합니다." 기한은 화면에서 계산하지 않고 **`view_expires_at`을 3.3 형식으로** 보인다. 확인 끝내기나 고정으로 연장되지 않는다 (D-92).
- 고정한 클립을 포함한 모든 영상은 업로드 완료 30일에 **한 번에** 파기된다 (D-64, D-80). 그때까지 여러 개의 고정 결과를 모두 볼 수 있다.

### 2.10 보관 기간 종료 화면 (`masked_deleted == true`)
- 업로드 완료에서 30일이 지나 원본·마스킹본·고정 클립이 **한 번에** 파기된 상태다 (D-57, D-64, D-80). 원본만 파기되고 마스킹본이 남는 경우는 없다.
- 정지 장면·후보 확인·결과 화면 전부 이 안내로 대체한다. 10·12·15번을 부르지 않는다.
- 안내 문구: "업로드 완료 후 30일이 지나 보관 기간이 끝났습니다. 영상은 안전하게 삭제되었습니다." "분석에 실패했다"로 읽히지 않게 쓴다.
- 다른 화면을 보던 중 `MASKED_EXPIRED`·`RAW_EXPIRED`를 받으면 9번을 다시 불러 이 화면으로 온다 (3.1).

## 3. 공통 에러 및 UX 항목

### 3.1 API 에러 문구 (D-38)
백엔드의 에러 응답 `code`로만 경우를 나눈다. `message`는 화면에 쓰지 않는다. 문구는 스낵바로 보이고, 처리는 [05장 5.11 "에러 code 한눈에 보기"](05-api.md#에러-code-한눈에-보기)를 따른다.

| `code` | 문구 | 화면 처리 |
|---|---|---|
| `UNAUTHENTICATED` (401) | "로그인이 필요합니다." | 로그인 화면으로 |
| `LOGIN_FAILED` (401) | "아이디 또는 비밀번호가 올바르지 않습니다." | 로그인 화면에 머문다 |
| `VIDEO_NOT_FOUND` (404) | "영상을 찾을 수 없습니다." | 영상 목록으로 |
| `CLIP_NOT_FOUND` (404) | "후보 영상을 찾을 수 없어 화면을 새로 고칩니다." | 12번(결과 화면이면 15번)을 다시 부른다 |
| `INVALID_STATE` (409) | "상태가 변경되었습니다. 최신 화면으로 새로고침합니다." | 9번을 다시 불러 화면을 새로 그린다 |
| `RAW_EXPIRED` (409) | "보관 기간(30일)이 지나 영상이 삭제되었습니다." | 9번을 다시 불러 보관 기간 종료 화면(2.10)으로 |
| `MASKED_EXPIRED` (409) | "보관 기간(30일)이 지나 영상이 삭제되었습니다." | 같다 |
| `VALIDATION_FAILED` (422) | "입력값이 올바르지 않습니다. 다시 입력해 주세요." | 입력을 다시 받는다. 12번이면 쿼리 없이 다시 부른다 |
| `UNSUPPORTED_FILE_TYPE` (422) | 업로드: 2.4 / 사진: "jpg, png, heic 사진만 올릴 수 있습니다." | 다른 파일을 고르게 한다 |
| `FILE_TOO_LARGE` (422) | 업로드: 2.4 / 사진: "사진은 20MB까지 올릴 수 있습니다." | 같다 |
| `UPLOAD_TOKEN_*` | 2.4 | |
| `INTERNAL_ERROR` (500) 및 그 밖 | "일시적인 시스템 오류가 발생했습니다. 잠시 후 다시 시도해 주세요." | 아무것도 바뀌지 않았다. 버튼을 다시 풀어 준다 |

- `VALIDATION_FAILED`는 화면이 먼저 막으므로 보통 나오지 않는다. 입력 화면의 규칙(차량 안 드래그는 [보임]일 때만, 꼬인 네 모서리, 이웃하지 않은 두 변)은 2.6에서 단계마다 막는다.
- 409는 대부분 "화면이 낡았다"는 뜻이다. 버튼을 감춰도 감춘 뒤 상태가 바뀔 수 있으므로 **화면마다 9번을 다시 불러 그리는 경로를 둔다** (05장 5.11).
- 6·11·13·14·17번과 분석 재시도 API(D-112, 05장 미정)는 보내는 즉시 버튼을 막는다 (05장 5.11).
- D-110(17번 고정 0개 거절)·D-112(재시도 거절, 횟수 소진)의 `code`는 05장에 아직 없다 ⚠️ (👤 팀원 2). 정해지기 전까지 화면은 "9번을 다시 불러 그린다"로 처리한다. 횟수 소진 문구는 2.5 "실패 안내"에 있다.

### 3.2 재생 URL 만료 처리 (D-41)
presigned URL이 15분 만료되어 S3에서 403 에러가 발생하면, 사용자에게 에러를 띄우지 않고 백그라운드에서 그 화면의 조회 API(10·12·15번)를 다시 불러 새 URL을 발급받아 끊긴 위치부터 이어 재생한다. 만료 시각을 계산하지 않는다. 다시 부른 API가 `MASKED_EXPIRED`면 3.1대로 한다.

### 3.3 열람기한 표시 (D-92)
- 영상 목록, 영상 상태, 후보 확인, 결과 화면에 `view_expires_at`을 **한국 시간으로 날짜와 시:분까지** 보인다: "YYYY-MM-DD HH:mm까지 열람 가능" (SRS 5.3, REQ-013). 기한은 업로드 완료 시각 + 30일이라 하루 중간에 끝나므로 날짜만 보이지 않는다.
- 브라우저의 시간대와 상관없이 `Asia/Seoul`(+09:00)로 바꿔 보인다. 표시 형식만 바꾸고 기한을 화면에서 계산하지 않는다.
- 업로드 완료 전이라 `null`이면 "업로드 완료 후 열람기한이 정해집니다"로 안내한다.

### 3.4 다운로드 차단 (불변 조건 8)
- 다운로드 버튼·링크를 두지 않는다. 재생은 `<video>` 스트리밍으로만 한다.
- 플레이어의 브라우저 기본 메뉴에서 저장 항목을 숨긴다(`controlsList="nodownload"`, 오른쪽 클릭 메뉴 막기) **(팀원 1 안)**. 개발자 도구로 받는 것은 막지 못한다 ([08장 8.9](08-auth.md#89-다운로드를-제공하지-않는-방법) 한계).

### 3.5 접근성(UX) 지원 (D-08, PRD 4장)
Flutter Web의 `Focus`와 `Shortcuts` 위젯을 활용해 마우스 없이 키보드만으로 핵심 조작이 가능하도록 구현한다.
- **영상 재생 제어**: 영상 플레이어에 포커스가 있을 때 `Spacebar`로 재생/일시정지, `←`/`→` 방향키로 앞/뒤 탐색을 지원한다.
- **버튼 조작**: 화면 내 주요 버튼(`[찾음]`, `[◀ 이전]`, `[다음 ▶]`, `[다음 묶음 받기]`, `[확인 끝내기]`, `[나중에 확인]`, `[목록으로]`, `[분석 다시 시도]`, 탭)은 `Tab` 키로 포커스를 이동할 수 있어야 하며, `Enter`나 `Spacebar`를 눌러 클릭 이벤트를 발생시킨다. 고정 해제 버튼은 없다 (D-40).
- 입력 화면의 그리기(드래그·점 찍기)는 마우스로만 한다.

### 3.6 와이어프레임
🚧 미작성 (팀원 1).

### 3.7 목록으로 돌아가기와 이어서 보기 (D-110, D-111)
- 영상 상태·입력·후보 확인·완료·결과 화면에 [목록으로]를 둔다. 후보 확인 화면에서는 이름을 **[나중에 확인]**으로 한다 **(팀원 1 안)** — 아직 볼 후보가 남아 있음을 드러낸다.
- [목록으로]·[나중에 확인]은 **서버를 부르지 않는다.** 17번(확인 끝내기)·13번(다음 묶음)을 부르지 않고, 보지 않은 후보를 "못 찾음"으로 넘기지 않는다. 분석 정지·재개도 없다. 분석 중이면 그대로 계속된다.
- 브라우저 뒤로 가기·탭 닫기도 같다. 아무것도 서버에 보내지 않는다.
- 다시 들어오면 늘 9번부터 불러 최신 상태로 화면을 고른다 (1장, 2.5). 앞에서 보던 화면을 기억해 두었다가 그대로 띄우지 않는다.
- 이어서 볼 수 있는 기한은 그 영상의 `view_expires_at`이다. 미뤘다고 늘어나지 않는다 (D-110). 기한이 지나면 보관 기간 종료 화면(2.10)이 나온다.
- 저장된 것: 입력(11번 저장 뒤), 받은 묶음, 넘긴 묶음, 고정. 저장되지 않는 것: 저장 전 입력, 재생 위치, 보던 탭 **(팀원 1 안: 다시 들어오면 [후보] 탭부터)**.
