# 07. 화면 설계

> 🚧 미작성. 작성할 항목과 이미 정해진 관련 결정만 적어 둔다.

> ⚠️ **D-67~D-75 반영 필요 (2026-09-27, 팀장).** 아래 "작성할 항목"은 아직 고치지 않았다. 바뀌어야 할 곳과 영향만 적는다. 팀원 1이 U-15에서 반영한다. 근거는 [11장](11-decisions.md), PRD 3.2·3.5.

## 작성할 항목

- 화면 목록과 화면 전환 (PRD 4장이 설계 문서로 미룬 세부 화면·문구, U-15)
- 화면별 구성요소와 Loading / Empty / Error 상태, 표시 문구
- 에러 문구: API 에러의 `code`별 한국어 문구 (코드 목록은 [05장 5.1](05-api.md#51-공통-규칙), D-38). 409 `INVALID_STATE`는 상태를 다시 조회해 화면을 새로 그린다
- 분석 상태 표시 (상태 목록은 04장, `uploading`·`upload_failed`는 05장 5.5)
  - 업로드 중: 관리자가 올리는 중이다. 이 영상은 아직 열 수 없다 (D-47)
  - 업로드가 확인되지 않음(`upload_failed`): **"실패"로 단정하지 않는다.** "업로드가 확인되지 않습니다 — 큰 파일이면 아직 올라오는 중일 수 있습니다. 한참 지나도 그대로면 관리자에게 확인하고, 중단됐다면 링크를 다시 발급하세요." (D-47)
  - 대기 중 (앞에 N건)
  - 1단계 분석 중 (입력 가능): 1단계가 끝나기 전에도 차량·파손 부위를 입력할 수 있다 (D-15). **입력은 한 번만 받는다** (D-66)
  - 입력 완료·1단계 진행 중, 2단계 분석 중, 확인 가능, 실패
  - GPU EC2를 켜는 중일 때의 대기 안내 (부팅 1~2분)
- 상태 조회 주기 (5~10초, U-18). 너무 자주 묻지 않는다 (D-19)
- 로그인 화면: 회원가입 화면은 없다. 계정은 미리 만들어 둔다 (D-44)
- 업로드 링크 발급 화면 (피해자용): 링크 발급, 유효 시간 안내, 재발급 (D-28). **발급 API는 버튼을 눌렀을 때만 부른다.** 화면을 열거나 새로 고칠 때 자동으로 부르면 이미 관리자에게 보낸 링크가 무효가 된다. 다시 발급하면 이전 링크가 무효가 된다는 것도 버튼 옆에 안내한다 (05장 5.4). 링크는 주차장 관리자에게 보여주는 용도라고 안내한다. 피해자가 원본을 직접 올리는 경로는 없다 (D-45)
- 관리자 업로드 화면: **로그인 없이 링크 주소로 여는 화면**이다 (D-28). 브라우저에서 S3로 직접 업로드, 진행률 표시, 업로드 완료 알림 (D-18). 5GB를 넘는 파일은 업로드 전에 막고 안내 문구를 보여준다 (D-22). 확장자가 `.mp4` `.avi` `.mkv` `.mov`가 아닌 파일도 업로드 전에 막고, 녹화기의 MP4·AVI 내보내기를 쓰라는 안내를 보여준다 (D-43). 만료·사용 완료된 링크의 안내 문구도 정한다
- 차량 선택·파손 부위 입력 화면 (D-65, D-66). 아래는 입력 방식에서 따라오는 요구사항이고, **화면 구성과 문구는 팀원 1이 U-15에서 정한다**
  - **① 차량 고르기.** 정지 장면 위에 10번 응답의 `detections`를 사각형으로 겹쳐 그리고, "본인 차량을 선택해주세요" 안내에 따라 **하나를 눌러 고른다.** 차량을 드래그하지 않는다 (D-65)
    - 고른 사각형을 다른 색·굵기로 강조하고, 고르기 전에는 다음 단계로 넘어가지 않는다
    - **겹친 사각형 중 어느 것이 잡히는지**를 정해야 한다 🚧. 주차장은 차가 많아 사각형이 겹친다. 누른 점을 품는 사각형이 여럿이면 **작은 것**(= 앞에 있어 덜 가려진 차)을 잡는 쪽이 자연스럽다 — 팀원 1이 정한다 (U-15)
    - 사각형이 많아 화면이 덮이면 선을 얇게 하고 채우기를 없애는 등 표시 방식을 정한다 🚧 (U-15)
  - **② 파손 부위 드래그.** "파손 부위를 드래그해주세요" 안내에 따라 **고른 차량 사각형 안에서** 드래그한다. 차량 영역 밖으로 그렸을 때의 안내 문구를 정한다
  - **③ 확인창.** 저장 전에 확인창을 띄운다. 고른 차량 사각형과 그린 파손 부위를 정지 장면 위에 함께 보여주고, **"저장한 뒤에는 고칠 수 없습니다"** 를 알린다. 취소하면 ①로 돌아간다. 문구는 여기서 정한다 🚧 (D-66, U-15)
  - 고르기와 드래그 사이에는 서버를 부르지 않는다. 확인창에서 [저장]을 눌렀을 때 11번을 한 번 부른다 (D-36, D-66)
  - **[다시 입력] 버튼은 없다.** 저장하면 고칠 수 없다. 상태 조회(05장 9번)의 `input_done`이 `true`면 입력 화면을 열지 않는다 (D-66). 화면이 오래돼 저장 버튼이 남아 있는 채로 눌리면 409 `INVALID_STATE`가 오므로 9번을 다시 부른다
  - 좌표는 원본 해상도 기준 픽셀로 보낸다. 화면이 이미지를 축소해 보여주더라도 `naturalWidth`·`naturalHeight`로 되돌려 계산한다 (05장 5.6, 5.7). 파손 부위는 고른 차량 사각형 안(경계 포함)에서만 받는다 — 밖으로 그리면 백엔드가 422로 거절한다 (05장 5.7)
  - **탐지가 0건이거나 목록에 본인 차가 없으면 재업로드 안내로 간다.** 차량을 드래그하는 폴백은 두지 않는다 (D-65). 아래 "다시 그리기와 재업로드 안내"와 **같은 화면**이므로 새 상태가 아니다 — [내 차가 목록에 없습니다] 버튼을 둘지와 문구만 정한다 🚧 (U-15)
  - 확장: 겹친 차를 픽셀 단위로 가르려면 다각형 외곽선 표시와 다각형 hit-test가 더해진다 🚧 (D-65, U-09)
  - 다시 그리기(취소)와, 정지 장면에서 본인 차량을 찾지 못했을 때의 재업로드 안내. **탐지가 0건이거나 목록에 본인 차가 없는 경우도 이 안내로 보낸다** (D-65). **정지 장면은 영상 시작 장면 1장이고 다른 시점으로 넘기는 버튼은 없다** (D-48). 가려졌든 아직 들어오지 않았든 이미 나갔든 안내는 재업로드 하나다 (PRD 3.2). 관리자에게는 **차가 이미 주차된 뒤부터 잘라 달라**고 안내한다 (업로드 화면 문구, U-15)
- 후보 확인 화면: 후보 영상, 후보마다 [찾음], 묶음 아래 [다음] 버튼 하나(= 묶음 전체 "못 찾음"), 남은 후보 수 (D-37). 조회 API는 05장 12번이다
  - **VLM 점수는 화면에 없다.** 배열 순서가 곧 점수순이고, API가 점수를 돌려주지 않는다 (05장 5.8)
  - 후보가 0건이면 후보 확인 화면 자체가 열리지 않는다. 상태가 바로 `exhausted`가 되므로(04장 전이 14) 아래 완료 화면으로 간다 (D-50)
- 완료(더 볼 후보 없음) 화면: `status`가 `exhausted`일 때. **문구는 `candidate_total`로 갈린다** (05장 9번, D-50)
  - `candidate_total > 0` — 사용자가 [다음]으로 전부 넘긴 경우. "모든 후보를 확인했습니다" (PRD 3.6)
  - `candidate_total == 0` — 후보가 애초에 없던 경우. "후보 구간이 탐지되지 않았습니다". **"사건 없음"으로 쓰지 않는다** (PRD 3.5). 재업로드·문의 안내를 둘지 정한다 🚧
  - 클립 안에서 사건 지점이 어디인지 표시할지 정한다. 위치는 `incident_at_sec − start_sec`다 (05장 5.8)
  - [다음] 버튼 이름, 누르기 전 확인창 여부, 다음 묶음을 만드는 동안(`batch_running`)의 대기 안내
  - **원본이 파기됐으면 [다음]을 보여주지 않는다.** 상태 조회(05장 9번)의 `raw_deleted`가 `true`일 때다. 원본이 없으면 다음 묶음의 후보 클립을 만들 수 없다 (D-52). `ready`인 채로 업로드 완료에서 30일이 지난 경우다 (D-64)
    - 지금 묶음은 그대로 볼 수 있다. 이미 만들어 둔 마스킹본이기 때문이다. **[찾음]도 그대로 쓸 수 있다** — 고정은 마스킹본 클립을 가리킬 뿐이라 원본이 필요 없다 (D-32)
    - [다음] 자리에 안내문을 둔다. 문구는 여기서 정한다 🚧 (U-15). 뜻은 "보관 기간(30일)이 지나 원본 영상이 파기돼 더 이상 후보를 만들 수 없다"이고, **"분석에 실패했다"로 읽히지 않게 쓴다.** 실패가 아니라 개인정보 보호를 위한 정상 동작이다
    - 화면이 오래돼 버튼이 남아 있는 채로 [다음]을 누르면 409 `RAW_EXPIRED`가 온다. 9번을 다시 불러 안내문으로 바꾼다 (05장 13번)
  - 이전 묶음으로 돌아가 다시 볼 수 있게 할지 🚧. **`ready`인 동안에만 가능한 기능이다** — 사건 확인이 끝나면(`pinned`·`exhausted`·`failed`) 고정한 클립 하나를 빼고 모두 파기된다 (D-64)
- 사건 지점 고정 화면: 원본 시간 위치 강조, 고정 전 확인. 고정 해제는 두지 않는다 (D-40). 조회 API는 05장 15번이다
  - 원본 기준 시작·끝(`start_sec`·`end_sec`)을 `03:40:35` 같은 형식으로 보여줄지 정한다. API는 초(실수)로 준다 (05장 5.9)
  - 다운로드 버튼을 두지 않는다 (불변 조건 8)
- **보관 기간 종료 화면**: 상태 조회(05장 9번)의 `masked_deleted`가 `true`일 때다. 업로드 완료에서 30일이 지나 마스킹본이 전부 파기된 상태다 (D-57)
  - 정지 장면·후보 확인·사건 지점 화면 **전부** 이 안내로 대체한다. 세 화면의 조회 API(10·12·15번)가 모두 409 `MASKED_EXPIRED`를 준다
  - **끝 상태에서는 정지 장면 조회(10번)만 따로 409가 된다** (D-64). 사건 확인이 끝나면 정지 장면이 먼저 파기되기 때문이다. `masked_deleted`는 아직 `false`이므로 이 화면으로 오지 않는다 — 끝 상태에서는 결과 화면이나 완료 화면을 보여주므로 정상 흐름에서는 걸리지 않고, 낡은 화면이 10번을 부를 때만 나온다
  - 문구는 여기서 정한다 🚧 (U-15). 뜻은 "보관 기간(30일)이 지나 영상이 삭제되었다"이고, `RAW_EXPIRED`와 마찬가지로 **"분석에 실패했다"로 읽히지 않게 쓴다**
  - **결과를 볼 수 있는 기간을 미리 알린다.** 기준이 업로드 완료 시각으로 고정이라 날짜를 계산해 보여줄 수 있다. 사건 지점 고정 화면에 "이 결과는 YYYY-MM-DD까지 볼 수 있습니다"를 둔다
- 영상·이미지 재생 공통: presigned URL이 만료돼 S3가 403을 주면 그 화면의 조회 API를 다시 불러 새 URL로 이어 재생한다. 재생 위치는 유지한다 (D-41, 05장 5.1)
- 와이어프레임
- PRD 4장 ⚠️ UX 항목 확정 (키보드 조작 등. 고정 전 확인과 사건 지점 해제 없음은 D-40으로 확정)

## 관련 결정·조건

- 완료 알림 대신 화면 상태 표시: D-05
- 차량·파손 부위 입력: D-29 / 우선 누끼 없이 드래그한 사각형을 그대로 표시, 한 번에 저장: D-36
- **본인 차량은 탐지된 차량 중에서 고른다. 파손 부위는 고른 차량 안에서 드래그한다: D-65** (폴백 없음 — 탐지 실패는 재업로드 안내)
- 후보마다 [찾음]만, 묶음 단위 [다음]이 "못 찾음": D-37
- 후보 0건이면 `exhausted` + `candidate_total`로 문구 구분: D-50
- 클립을 못 만든 후보는 목록에서 빠진다(화면 변경 없음): D-51
- 원본 파기 뒤에는 [다음]을 감추고 안내문을 보여준다: D-52, `raw_deleted`는 05장 9번 / 파기 시점은 끝 상태와 업로드 완료 30일 뒤 둘뿐: D-64
- 마스킹본 파기(업로드 완료 30일) 뒤에는 결과 화면을 안내문으로 대체한다: D-57, `masked_deleted`는 05장 9번 / 끝 상태에서는 고정한 사건 클립만 남는다: D-64
- 1단계 중 입력 허용, GPU 켜기 대기: D-15
