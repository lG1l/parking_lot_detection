한 줄 요약

사용자가 찍어 준 바닥 네 점과 차량 bbox만으로 "사건의 단서가 화면 어디에 나타날지"를 자동으로 정해서, 그 범위 안의 움직임을 보고 후보 탐지를 시작한다. 카메라 높이를 미터로 알아내려는 게 아니다.

1. 무엇을 해결하려는가

ROI(관심 영역)는 "이 안에서 움직임이 보이면 분석을 시작하라"고 정해 두는 화면 속 범위입니다. 같은 차를 봐도 카메라 위치에 따라 이 범위가 달라져야 합니다.

🔽 카메라가 낮을 때차 너머 바닥은 차에 가려집니다. 파손 변 바깥 바닥만 보면, 지붕 위로 보이는 사람 머리나 차 앞뒤로 드나드는 움직임을 놓칩니다.
🔼 카메라가 높을 때주변 바닥이 잘 보입니다. 이때도 낮은 카메라와 똑같이 넓게 보면, 상관없는 움직임이 너무 많이 들어옵니다.
📏 차가 작게/크게 찍힐 때"여유 50px"처럼 고정 픽셀을 주면, 작은 차에는 너무 크고 큰 차에는 너무 작습니다. 그래서 차 크기에 비례해야 합니다.
🔄 차가 비스듬할 때화면의 좌우·상하와 차의 앞뒤·좌우가 일치하지 않습니다. 차 방향에 맞춰 영역을 만들어야 합니다.
입력받지 않는 것: 카메라 내부 정보, 실제 차량 치수, 실제 거리, 주차면 실측 크기. 대신 "차가 화면에서 차지하는 크기"를 자로 씁니다.

2. 어떤 정보를 어디에 쓰나

이미 받고 있는 정보(원본 해상도·본인 차량 bbox·바닥 네 모서리·파손 변·보임/안 보임·파손 사각형)에 정면 변 하나를 더 받자는 것이 원문의 제안입니다. 각 정보에는 "맡길 일"과 "맡기면 안 되는 일"이 정해져 있습니다.

정보맡기는 일맡기면 안 되는 일
바닥 네 모서리차 바닥 경계, 주변 영역의 방향, 대략적인 원근정확한 지붕·사람 머리 위치
정면 변차의 길이 방향/폭 방향 구분카메라가 어느 쪽에 있는지 단독 판정
차량 bbox화면상 차 크기, 크롭 최소 범위, 높이 방향 여유의 기준실제 차체 높이·정확한 외곽선
파손 변어느 면 주변 움직임을 우선 볼지그 면이 실제로 보인다는 추정
보임/안 보임직접 관측 중심 vs 가려진 쪽 접근 중심으로 분기주변 바닥이 다 보인다는 보장
파손 사각형보임: 접촉 위치 / 안 보임: 사용자가 지목한 위치 참고안 보임 입력을 실제 관측 좌표로 사용

이 설계는 규칙 기반 자동 계산입니다. 매번 사람이 ROI를 그리거나 VLM이 영역을 만들지 않습니다. 사진·텍스트 설명은 영역 계산에 쓰지 않습니다(해석이 개입하면 같은 입력에서 결과가 달라질 수 있어서).

3. 바닥 네 점과 정면 변

  • 정면 변은 기존 네 변 중 하나를 고르게 합니다. 새 점을 더 찍게 하지 않습니다. 원근 때문에 화면에서 가장 짧은 변이 정면일 거라고 추정하지 않습니다.
  • 정면을 모르겠다는 응답도 허용합니다. 이때는 길이·폭을 가정하는 계산을 건너뛰고 넓은 대체 영역을 씁니다.
  • 정면 정보가 해 주는 일은 차 좌표 방향 확정뿐입니다. 촬영 각도를 정확히 얻게 해 주지는 않습니다.
  • 바닥 네 점의 뜻을 "차체 외곽을 바닥으로 내린 네 모서리"로 통일하자는 제안이 있습니다. 바퀴 중심·접지점과 섞으면 주변 띠의 시작점과 길이·폭 비율이 달라지기 때문입니다. 점은 차 둘레를 따라 순서대로 찍습니다.

4. 바닥 띠 만들기 — "고무판" 비유

찌그러져 보이는 네 점 사각형을 고무판이라고 생각해 봅니다. 이 고무판을 반듯한 직사각형(차 바닥을 위에서 본 모양)으로 펴면, 그 위에서는 "차 폭의 0.5배 바깥"처럼 차 크기 단위로 쉽게 띠를 그릴 수 있습니다. 그린 띠를 다시 고무판 모양으로 되돌리면 화면 속 원근에 맞게 찍힙니다. 이 변환을 호모그래피라고 부르며, 미터도 카메라 정보도 필요 없고 점 네 쌍만 있으면 됩니다.

파손 위치별로 띠 만드는 법

옆면 파손바깥 여유 = 차 폭 비율, 양 끝 여유 = 차 길이 비율
앞·뒤 범퍼 파손바깥 여유 = 차 길이 비율, 양 끝 여유 = 차 폭 비율
모서리 파손선택한 두 변의 띠를 각각 만들어 합친다. 평균 방향으로 띠 하나를 만들지 않는다

주의: 폭과 길이를 각각 1로 둔 좌표라서 두 축의 단위가 다릅니다. 이 좌표에서 거리를 재서 실제 거리처럼 비교하면 안 됩니다.

이 변환을 믿을 수 없을 때

변환은 네 점 안에서는 그럴듯해도 바깥으로 넓히면 갑자기 크게 벌어질 수 있습니다. 아래 경우에는 해당 띠를 신뢰하지 않습니다.

  1. 사각형이 거의 일직선이거나 면적이 너무 작다.
  2. 넓힌 띠가 뒤집히거나 교차하거나 경계가 발산한다.
  3. 점을 조금만 옮겨도 띠가 화면 반대편까지 이동한다.
  4. 결과가 차 크기에 비해 지나치게 크다(판정 배수는 조정용 영상으로 정함).

이때는 작은 사각형으로 억지로 자르지 않고, 파손 변을 포함하는 화면 범위를 bbox 크기에 비례해 넓히는 대체 규칙을 씁니다. 파손 변 자체도 불안정하면 차 bbox 전체 주변을 감시합니다.

5. 움직임 ROI — 네 조각의 합집합

ROI는 "이 안의 움직임을 단서로 후보 탐지를 시작하는 영역"입니다. 물체가 계속 ROI 안에 있어야 한다는 뜻은 아닙니다. 모양은 사각형이 아니라 아래 네 조각을 합친 마스크이고, 실제로 프레임을 자르는 크롭은 사각형입니다.

조각무엇을 잡으려고만드는 기준
파손 위치 주변접촉·문·손·물체 끝의 움직임파손 사각형에 여유
파손 변 바깥 바닥 띠접근·머무름·바퀴와 발4장의 상대 좌표 띠
높이 방향 확장발은 가려져도 나타나는 상체·물체 윗부분바닥 띠 + bbox 세로 크기
양 끝 출입 영역차 너머 진입·이탈·재등장파손 변 양 끝 + 주변 여유

보이는 파손일 때 순서

  1. 파손 사각형을 확장해 직접 접촉 영역을 만든다.
  2. 파손 변의 바닥 띠를 더한다(사각형만 보면 접근 과정이 빠질 수 있어서).
  3. 바닥 띠를 위쪽으로 쓸어 올린 영역을 더한다(원래 띠부터 올린 띠까지 사이를 모두 포함).
  4. 변 양 끝의 출입 여유를 더한다.
  5. 검증된 "내려다봄" 구도에서는 높이 확장을 줄이고, "낮게 봄"·"불확실"에서는 더 크게 쓴다.

직접 보이는 손·문·공중 물체의 움직임은 "바닥 띠 밖"이라는 이유로 지우지 않습니다.

안 보이는 파손일 때 순서 (가장 중요한 분기)

안 보이는 이유는 우리 차 반대편일 수도, 옆 차량·기둥일 수도 있는데 지금 입력으로는 구분할 수 없습니다. 그래서 안 보임이면 높은 구도로 추정돼도 좁은 ROI를 바로 고르지 않습니다.

  1. 선택한 파손 변의 바닥 띠와 양 끝 출입 영역을 만든다(파손 사각형이 작아도 변의 일부만 남기지 않음).
  2. 띠와 출입 영역을 위로 확장한다 — 각 영역의 가로 범위 안에서 차 bbox 상단보다 추가 여유만큼 더 위까지 연결.
  3. 이 확장은 사람 키를 복원한 것이 아니라, 차 너머로 나타날 신호를 넉넉히 포함하려는 근사다.
  4. 사용자가 지정한 파손 사각형과 주변도 합치되, 가려진 표면의 정확한 위치로 보지 않는다.
  5. 입력·변환이 불안정하면 차 bbox 전체 주변의 넓은 대체 ROI로 바꾼다.
높은 시점에서 안 보이는 파손도 줄이고 싶다면, 카메라 높이 대신 "파손된 쪽 바로 옆 바닥과 사람이 드나드는 공간이 보이나요?(보임/가림/모르겠음)"를 추가로 묻는 안이 원문에 선택지로 있습니다. 기본안에는 넣지 않았고, 추가 입력이 없다면 높은 시점의 안 보임도 넓게 처리하는 비용을 받아들여야 합니다.

6. 확장량 시작값

아래 숫자는 실험 시작값 제안입니다. 성능이 검증된 값이 아니고, 팀장 승인과 조정용 영상 검증 없이 확정값으로 쓰지 않습니다.

항목시작값이유와 위험
옆면 바깥 바닥 여유차 폭의 0.5배옆 공간 접근 포함. 긴 문·큰 물체에는 부족할 수 있음
범퍼 바깥 바닥 여유차 길이의 0.25배앞뒤 접근 포함. 급한 접근·큰 차량은 별도 확인
바닥 띠 양 끝 여유해당 변 길이의 각 0.2배모서리 접근 포함. 원근이 강하면 변환 불안정
파손 사각형 확장좌우 bbox 폭의 0.15배, 상하 bbox 높이의 0.15배작은 입력 누락 완화. 배경 반사 유입
보임 · 내려다봄 높이 확장bbox 높이의 0.25배바닥 밖 손·물체를 위한 최소 여유
보임 · 낮게 봄/불확실 높이 확장bbox 높이의 0.75배더 넓은 세로 범위 확보
안 보임 상단 여유bbox 상단에서 bbox 높이의 0.5배 더 위까지지붕 위 움직임 확보. 차가 높거나 원근에 따라 부족/과대 가능
양 끝 출입 영역끝점 주변 좌우 bbox 폭의 0.25배, 상하 높이의 0.25배가려짐 전후 움직임 포함
계산 실패 시 대체 ROIbbox를 좌우 각 폭의 0.5배, 위 높이의 0.75배, 아래 높이의 0.25배 확장방향을 못 믿을 때 넓게 탐색. 후보·처리량 증가

예시: bbox 높이가 200px인 차에는 "높이의 0.5배 여유"가 100px, 80px인 차에는 40px입니다. 같은 규칙이 차 크기에 맞춰 자동으로 달라집니다.

조정 요령: 머리를 놓쳤으면 위쪽 여유, 출입을 놓쳤으면 끝점 여유, 문 끝을 놓쳤으면 바깥 띠·파손 주변 여유를 조정합니다. 모든 배수를 동시에 키워 원인을 숨기지 않습니다.

7. 보여줄 크롭과 분석 크롭

순서는 ROI 먼저 → 보여줄 크롭 → 분석 크롭입니다. ROI가 위로 커지면 두 크롭도 같이 커집니다.

  • 보여줄 크롭: 차 bbox와 화면 안 ROI 전체를 감싸는 최소 사각형 + 보기 여유(좌우 각 bbox 폭의 0.1배, 상하 각 높이의 0.1배) → 필요한 영역을 깎지 않고 모자란 축을 늘려 16:9로 → 가능하면 원본 안으로 이동(이동 뒤에도 포함 여부 재검사).
  • 분석 크롭: 완성된 보여줄 크롭에 좌우 각 bbox 폭의 0.5배, 상하 각 높이의 0.5배를 더하는 안부터 시험 → 16:9 맞추고 원본 안에서 위치 조정. 영상 하나에서는 같은 크롭을 유지하고, 움직임마다 중심을 옮기지 않습니다.
  • 화면 경계와 16:9가 충돌할 때(세로 영상·4:3 등): 필요한 원본 영역을 보존하고 남는 부분은 패딩으로 채워 16:9로 만드는 예외안을 제안합니다. 패딩은 원본 픽셀이 아니므로 움직임 감지에서 제외합니다. 기존 D-175의 원본 비율 예외에 대한 새 제안이라 담당자 검토가 필요합니다.
  • 크롭을 넓히면 물체가 작아집니다. 같은 입력 해상도로 줄이면 사람·작은 물체가 더 작게 보이므로, 필요한 ROI를 입력 크기에 맞추려고 자르지 않고 해상도·처리 시간을 함께 확인합니다.

8. 구도 추정 — 높이 정도를 어떻게 짐작하나

원문은 "카메라가 높은가 낮은가"를 다음 방식으로 상대적으로 짐작해 보자고 합니다. 단, 도 단위 각도나 CCTV 위치를 출력하지는 않습니다.

  1. 정면·후면 변의 같은 방향 벡터를 평균 → 화면상 폭 방향
  2. 양쪽 측면 변을 평균 → 화면상 길이 방향
  3. 길이 방향 벡터를 "가정한 길이÷폭 비율"로 나눠 보정 (미터 치수는 쓰지 않음)
  4. 두 벡터로 만든 2차원 변환의 큰 축·작은 축 길이를 구함(SVD)
  5. 작은 축÷큰 축 = 바닥 눌림 지표. 0에 가까울수록 한 방향이 강하게 눌린 것

이렇게 하는 이유는 단순한 "바닥 박스 세로÷가로"가 차가 회전하면 카메라가 그대로여도 달라지기 때문입니다. 다만 바닥이 직사각형이고, 종횡비 가정이 맞고, 차 내부 원근 차이가 작을 때만 내려다보는 정도와 연결됩니다. 처음 비교할 종횡비 후보는 2.0, 2.5, 3.0입니다. 후보에 따라 결과가 크게 바뀌면 구도를 "불확실"로 처리합니다.

보조 단서: 바닥 면적÷bbox 면적, 바닥 맨 위와 bbox 상단의 간격÷bbox 높이, 마주 보는 변의 길이 차이, 점을 조금 옮겼을 때 판정이 바뀌는지(각 점을 2px와 bbox 대각선의 1% 중 큰 값만큼 이동).

내려다봄여러 단서와 민감도 시험이 일관되게 위에서 보는 형태 → 보이는 파손에 한해 좁은 확장 검토
낮게 봄바닥이 강하게 눌리고 차체 세로 범위가 두드러짐 → 높이 방향·출입 경로 여유 확대
불확실단서 충돌, 정면 미상, 강한 원근, 작은 차, 불안정한 입력 → 넓은 대체 영역
분류 경계값과 단서 결합 규칙은 아직 검증되지 않았습니다. 원문은 "초기 구현은 구도에 의한 자동 축소를 끈 상태로 시작하고, 조정용 영상에서 검증한 뒤 켠다"고 제안합니다. 넓은 기준 영역은 처음부터 자동 생성하고, 축소 기능만 따로 검증해서 누락이 늘어나는지 기준안과 직접 비교하겠다는 뜻입니다.

9. 상황별로 어떻게 동작하나

상황처리남는 한계
거의 수직으로 내려다봄 + 파손 보임검증되면 좁은 바닥 띠·짧은 높이 확장문·손·공중 물체용 최소 여유 필요
낮게 옆에서 봄 + 파손 보임직접 접촉 영역 + 넓은 높이·출입 여유가까운 무관한 통행도 들어옴
낮게 봄 + 반대편 파손 안 보임바닥 띠 + bbox 상단 위까지 확장 + 양 끝 출입차보다 낮게 완전히 숨은 물체는 관측 불가
높게 봄 + 파손 안 보임구도만으로 줄이지 않고 넓은 안 보임 규칙옆 차·기둥 가림 이유를 입력만으로 알 수 없음
중간 높이 또는 단서 충돌"불확실"로 넓게 처리처리량·오탐 증가
정면·후면에서 촬영정면 선택으로 길이·폭 대응 유지화면상 짧은 변만으로 구도 판정 금지
차가 대각선으로 주차차 상대 좌표에서 띠를 만들어 영상으로 변환화면 수평 띠만 쓰는 오류를 막음
모서리 파손(두 변)두 변 ROI의 합집합범위가 넓어질 수 있음
작고 먼 차량bbox 비례 계산 후 원본·모델 입력 해상도 검사. 불안정하면 넓은 규칙원본에 없는 세부는 복구 불가
크고 가까운 차량필요한 영역 보존하며 화면 경계 처리화면 밖 접근 단서는 얻을 수 없음
일부가 화면 밖으로 잘린 차정상 기하 추정으로 취급하지 않음, 보이는 범위의 대체 ROI실제 관측 범위는 늘지 않음
옆 차·기둥에 가림안 보임의 넓은 규칙높게 찍혔다고 가림이 해결되지는 않음
트럭·특수차·형태 다른 RC카종횡비 가정을 믿지 않고 구도 축소 중단넓은 ROI 비용
네 점이 꼬임·중복저장 전 입력 오류로 재지정. 이미 저장된 비정상 자료는 계약 오류잘못된 형식이 조용히 통과하지 않음
네 점은 유효하지만 매우 납작함낮은 시점일 수 있으니 거절하지 않고, 기하 확장 대신 대체 ROI낮은 시점과 부정확한 입력을 완전히 구분 못 함
심한 어안·화면 회전·경사 바닥검증 범위 밖으로 표시, 시험 시 사방 여유의 넓은 대체 ROI방향별 정확한 축소를 지원한다고 주장하지 않음
영상 도중 카메라 이동·줌최초 고정 영역 전제가 깨짐. 정책은 별도 결정자동 추종은 가정하지 않음
접근·접촉·이탈이 모두 안 보임관측 불가로 한계 기록ROI 확대·VLM으로 복원 불가

후보 탐지와의 연결

  • ROI에 들어온 움직임은 분석을 시작할 단서일 뿐, 닿았다고 접촉 후보를 확정하지 않습니다.
  • 객체 탐지·추적은 분석 크롭에서 하고, ROI 밖으로 나갔다고 트랙을 지우지 않습니다.
  • 물체 바닥점이 불안정하거나 가려졌으면 ROI·띠 밖이라는 이유로 접촉 가능성을 배제하지 않습니다(D-91).
  • ROI를 놓치면 채널 A가 켜지지 않을 수 있으므로 "ROI 포함"과 "객체 탐지 성능"을 따로 확인합니다.
  • 움직임이 전혀 없는 접촉도 있어서 "접촉이면 반드시 ROI 픽셀 변화가 있다"는 보장은 하지 않습니다.
  • D-165의 ROI 전용 움직임 계산과 D-96의 분석 크롭 전체 연결 요소 확장은 조정이 남아 있고, 이 문서는 ROI 마스크만 정의합니다.

10. 검증 방법과 아직 정해지지 않은 것

비교할 세 가지 안

  1. 차 bbox를 넓힌 단순 기준안
  2. 네 점·정면·bbox를 쓰되 구도에 따른 자동 축소는 하지 않는 안
  3. 2번에 검증된 구도 분류와 축소 규칙을 더한 안

3번이 ROI를 줄이면서도 사건 단서를 놓치지 않는지 확인해야 구도 추정의 이점이 입증됩니다. "작은 ROI가 그려졌다"는 것만으로는 성공이 아닙니다.

확인 자료: 높음·중간·낮음 시점, 정면·측면·대각선, 보임·안 보임을 나눠 확인하고, 사람·옆 차 문·주행 차량·작은 물체를 구분합니다. RC카만으로 사람 머리·문콕의 범용성을 검증했다고 말하지 않습니다. 극단 구도는 합성 투영으로 계산 성질을 시험할 수 있지만 실제 성능 검증을 대신하지는 않습니다.

개발용 겹침 그림: 원본 위에 bbox, 네 점, 각 ROI 조각, 최종 ROI, 두 크롭을 색으로 겹쳐 저장합니다. 개발·검증용이며 사용자 크롭 미리보기 제외 결정(D-176)을 바꾸지 않습니다.

설계를 확정하기 전에 충족할 조건

  1. 같은 입력·같은 규칙 버전이면 같은 결과가 나온다.
  2. 정상·낮은 시점·기하 계산 실패·화면 경계 각각에 실행 경로가 있다.
  3. 화면 안 ROI와 차 bbox가 보여줄 영역에, 그 영역이 분석 영역에 포함된다.
  4. 지붕 위 움직임과 양 끝 출입을 따로 검증한다.
  5. 높은 시점에서 작은 ROI를 고르는 조건을 조정용 자료로 뒷받침한다. 근거가 없으면 자동 축소를 켜지 않는다.
  6. 실제 자료가 없는 상황은 "미검증"으로 남긴다.
