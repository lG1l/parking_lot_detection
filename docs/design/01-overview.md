## 1.4 작성 규칙

사람과 에이전트 모두 이 규칙을 따른다.

- 결정은 [11장](11-decisions.md)에 `D-01` 형식의 ID로 기록한다. 본문에는 결과만 적고 `(D-05)`처럼 근거를 링크한다.
- **새로 기록하는 결정은 상태를 "확정 필요"로 적는다.** 팀이 함께 검토한 뒤에만 "확정"으로 바꾼다. 한 사람과의 논의로 정한 것을 "확정"으로 적으면 다른 팀원이 검토 없이 구현한다. ([11장 상태 표기](11-decisions.md#목차))
- 결정을 바꿀 때는 기존 기록을 지우지 않는다. 새 결정을 추가하고 기존 결정에 "D-xx로 대체됨"을 표시한다.
- 미정 항목은 🚧로 표시하고 11장 미결정 목록에 `U-01` 형식의 ID로 올린다.
- 수치 상수는 [1.6](#16-주요-상수)에만 적고 다른 곳에서는 이름으로 참조한다.
- API·파일 형식 같은 인터페이스는 설명보다 예시 JSON으로 적는다.
- 반드시 지켜야 하는 규칙(불변 조건)은 [02장 2.4](02-architecture.md#24-이중-경로와-불변-조건)에 모아 둔다. 코드와 테스트는 이 조건을 기준으로 작성한다.

## 1.5 용어집

문서와 코드에서 아래 용어를 이 뜻으로만 쓴다.

**사람·역할**

| 용어 | 뜻 |
|---|---|
| 사용자 (피해자) | 차량이 파손되어 CCTV를 확인하려는 사람. 서비스 계정의 주인이다. |
| 관리자 | 주차장 관리자. 사용자의 계정으로 CCTV 영상을 업로드한다. |

**영상·시간**

| 용어 | 뜻 |
|---|---|
| 원본 영상 | 관리자가 업로드한 파일 그대로의 영상. 분석에만 쓰고 사용자에게는 절대 보여주지 않는다. |
| 원본 시간 | 원본 영상 시작부터의 경과 시간(초). 모든 시간 정보의 기준이다. |
| 청크 | 분석을 위해 원본 영상을 시간 단위로 나눈 구간. 원본 시간 기준 시작·끝을 가진다. |
| 샘플링 fps | 분석할 때 초당 몇 장의 프레임을 뽑아 탐지할지 정한 값. |
| 정지 장면 | 차량 선택용 프레임. 원본 영상 **시작 장면(첫 프레임) 1장**이다. 1단계가 만드는 유일한 산출물이다 (D-67). 다른 시점으로 넘겨 보는 기능은 없다. (PRD 3.2, D-48) |
| 비식별화 | 번호판과 사람 **얼굴**을 모자이크 처리하는 작업. 얼굴을 찾지 못한 사람 트랙은 사람 전체를 가린다 (D-69). "마스킹"·"모자이크"와 같은 뜻이며, 문서에서는 "비식별화"로 통일한다. |
| 마스킹본 | 비식별화가 끝난 영상·이미지. 사용자에게는 마스킹본만 보여준다. |
| 이중 경로 | 분석은 원본 영상으로, 열람은 마스킹본으로 하는 원칙. (PRD 3.1) |

**분석**

| 용어 | 뜻 |
|---|---|
| 객체탐지 | 프레임에서 차·사람의 위치(bbox)를 찾는 작업. YOLO 계열 모델을 쓴다. |
| 추적 (트래킹) | 프레임마다 탐지된 bbox를 이어 붙여 같은 객체에 같은 ID를 주는 작업. ByteTrack을 쓴다. |
| 트랙 | 추적 결과로 만들어진 객체 하나의 시간별 bbox 목록(궤적). |
| 차량 영역 | 사용자가 정지 장면에서 **고른** 본인 차량의 사각형. 탐지 결과의 bbox다. 2단계 룰이 쓴다. (D-65) |
| 누끼 | 탐지 결과로 딴 차량 외곽(다각형). **쓰지 않는다** — 차량 영역은 bbox다. 겹친 차를 픽셀 단위로 가르려면 필요해진다 🚧 (D-65, U-09) |
| 탐지 목록 (`detections`) | 정지 장면에서 탐지된 차량들의 `det_id` + `bbox`. 화면이 이미지 위에 겹쳐 그리고 사용자가 하나를 고른다. (D-65) |
| 본인 차량 | 사용자가 정지 장면의 탐지 목록에서 골라 지정한 자신의 차량. (D-65) |
| 파손 부위 | 사용자가 입력한 본인 차량의 파손 위치. **고른 차량 영역 안에서 드래그**한다. (D-65) |
| 인접 영역 | 파손 부위가 CCTV에 보이지 않을 때 대신 감시하는 파손 부위 쪽 공간(옆 주차면, 통로). 입력 방식은 🚧 (PRD 3.3, U-25) |
| 탐지 상황 | 사용자가 고르는 "파손이 CCTV에 **보임 / 안 보임**". 룰이 이 값으로 갈린다. (D-72) |
| 근접 영역 (ROI) | 본인 차량 bbox를 넓힌 영역. 채널 B가 이 안에서만 움직임을 찾는다. 크기 🚧 (D-71, U-30) |
| 채널 A / 채널 B | 후보 탐지의 두 경로. A = 객체탐지 + 추적(프레임 전체). B = 근접 영역의 움직임 덩어리 + 추적(클래스 없는 물체용). (D-71) |
| 바닥점 | 트랙 bbox 아래 변의 가운데. 물체가 바닥에 닿는 자리로 본다. (D-71) |
| 바닥선 | 본인 차량이 바닥에 닿는 경계. 처음에는 차량 bbox 아래 변. (D-71) |
| 띠 | 바닥선 바로 아래의 좁은 영역. 폭은 차량 bbox 높이에 비례한다. 바닥점이 띠 안이면 근접이다. (D-71) |
| 0단계 필터 | VLM 전에 트랙을 거르는 규칙. **확실히 관계없는 것만 빼고, 판단이 안 되면 남긴다.** (D-71) |
| 룰 | 트랙과 파손 부위·인접 영역의 위치 관계로 근접을 판정하는 규칙. 바닥점 필터와 0단계 필터로 이뤄진다 (D-71). 후보 병합 등은 🚧 (U-13) |
| 판정 시점 (기준점) | 룰이 후보로 판정한 원본 시간. 트랙 바닥점이 파손 부위에 가장 가까운 순간이다. VLM은 이 ±1초를 조밀하게 본다 ⚠️ (D-73, U-31) |
| 후보 | 룰이 판정한 근접 순간 하나. 판정 시점을 가진다. 연속된 판정을 하나로 합치는 규칙은 🚧 (U-13) |
| VLM 점수 | Bedrock VLM이 후보마다 따로 매긴 접촉 가능성 점수(0~100). 정렬에만 쓴다. **2차 VLM에서만 나온다.** 1차에서 탈락한 후보는 0점이다. (D-74) |
| 1차 VLM / 2차 VLM | 1차 = 싼 모델(Nova Lite, 잠정)이 확실히 아닌 후보만 탈락시킨다. 2차 = Claude Haiku 4.5가 남은 후보에 점수를 매긴다. (D-74) |
| 안내 프레임 | VLM에 보내는 후보 구간 첫 프레임 1장. 파손 부위(안 보임이면 인접 영역) 테두리를 그려 "어디를 볼지" 알린다. (D-73) |
| 1단계 분석 | 업로드 직후 자동 실행하는 분석. 코덱 검사, 정지 장면 추출, 차량 탐지, 정지 장면 비식별화만 한다. 짧다(수십 초, 추정). GPU 워커가 실행한다. (D-67, D-14, D-65) |
| 2단계 분석 | 사용자 입력을 저장하면 실행하는 분석. 청크별 객체탐지·추적(채널 A·B), 0단계 필터, VLM 1차·2차, 정렬, 상위 20개 후보 클립 크롭·비식별화. 24시간 영상 약 30분(추정). GPU 워커가 실행한다. (D-67, D-14) |

**확인·결과**

| 용어 | 뜻 |
|---|---|
| 사건 지점 | 판정 시점 + 5초. 후보 클립의 가운데 시점이다. (PRD 3.5) |
| 후보 클립 | 사건 지점 전후 15초(판정 시점 −10초 ~ +20초), 총 30초 길이의 마스킹본 영상. **본인 차량 주변으로 크롭한다** (D-70). 영상 경계를 넘는 부분은 잘라낸다. |
| 후보 묶음 | 한 번에 제공하는 후보 클립 최대 10개. |
| 사건 지점 고정 | 사용자가 "찾음"을 고른 후보 클립을 클라우드에 저장하고, 원본 시간 기준 시작~끝을 표시하는 것. (PRD 3.6) |
| 후보 전부 확인 완료 | 모든 후보를 "못 찾음"으로 확인한 상태. 사건이 없다는 뜻이 아니다. (PRD 3.6) |

**인프라**

| 용어 | 뜻 |
|---|---|
| 백엔드 EC2 | 웹 정적 파일, FastAPI API 서버, PostgreSQL을 실행하는 CPU 인스턴스. 통신과 관리만 하고 영상 분석은 하지 않는다. (D-10, D-14, D-17) |
| GPU EC2 (GPU 워커) | 1단계·2단계 분석을 모두 실행하는 GPU 인스턴스. 업로드 남은 시간이 임계 이하가 될 때 켜지고, 15분 동안 할 일이 없으면 스스로 꺼진다. (D-10, D-14, D-15, D-62) |
| SQS 작업 대기열 | 백엔드가 분석 작업을 넣고 GPU 워커가 꺼내 가는 AWS 대기열. 메시지에는 작업 ID만 넣는다. (D-16) |
| 작업 상태 | 작업이 지금 어느 단계인지(대기 중, 1단계 분석 중, 확인 가능, 실패 등). SQS가 아니라 DB에 기록한다. (D-16) |
| presigned URL | 서명이 들어간, 일정 시간만 유효한 S3 임시 주소. 원본 업로드와 마스킹본 재생에 쓴다. (D-09, D-18) |
| 가짜 워커 | GPU·Bedrock 없이 정해진 시간 기다린 뒤 가짜 결과를 쓰는 워커 실행 방식. 부하 테스트와 로컬 개발에 쓴다. (D-20) |
| 무상태 API | 서버 메모리에 사용자·작업 정보를 두지 않는 API. 어느 서버가 요청을 받아도 같은 결과를 돌려주므로 서버를 여러 대로 늘릴 수 있다. (D-19) |
