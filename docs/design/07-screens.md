# 07. 화면 설계

> 🚧 미작성. 작성할 항목과 이미 정해진 관련 결정만 적어 둔다.

## 작성할 항목

- 화면 목록과 화면 전환 (PRD 4장이 설계 문서로 미룬 세부 화면·문구, U-15)
- 화면별 구성요소와 Loading / Empty / Error 상태, 표시 문구
- 에러 문구: API 에러의 `code`별 한국어 문구 (코드 목록은 [05장 5.1](05-api.md#51-공통-규칙), D-38). 409 `INVALID_STATE`는 상태를 다시 조회해 화면을 새로 그린다
- 분석 상태 표시 (상태 목록은 04장, `uploading`·`upload_failed`는 05장 5.5)
  - 업로드 중: 관리자가 올리는 중이다. 이 영상은 아직 열 수 없다 (D-47)
  - 업로드가 확인되지 않음(`upload_failed`): **"실패"로 단정하지 않는다.** "업로드가 확인되지 않습니다 — 큰 파일이면 아직 올라오는 중일 수 있습니다. 한참 지나도 그대로면 관리자에게 확인하고, 중단됐다면 링크를 다시 발급하세요." (D-47)
  - 대기 중 (앞에 N건)
  - 1단계 분석 중 (입력 가능): 1단계가 끝나기 전에도 차량·파손 부위를 입력할 수 있다 (D-15)
  - 입력 완료·1단계 진행 중, 2단계 분석 중, 확인 가능, 실패
  - GPU EC2를 켜는 중일 때의 대기 안내 (부팅 1~2분)
- 상태 조회 주기 (5~10초, U-18). 너무 자주 묻지 않는다 (D-19)
- 로그인 화면: 회원가입 화면은 없다. 계정은 미리 만들어 둔다 (D-44)
- 업로드 링크 발급 화면 (피해자용): 링크 발급, 유효 시간 안내, 재발급 (D-28). **발급 API는 버튼을 눌렀을 때만 부른다.** 화면을 열거나 새로 고칠 때 자동으로 부르면 이미 관리자에게 보낸 링크가 무효가 된다. 다시 발급하면 이전 링크가 무효가 된다는 것도 버튼 옆에 안내한다 (05장 5.4). 링크는 주차장 관리자에게 보여주는 용도라고 안내한다. 피해자가 원본을 직접 올리는 경로는 없다 (D-45)
- 관리자 업로드 화면: **로그인 없이 링크 주소로 여는 화면**이다 (D-28). 브라우저에서 S3로 직접 업로드, 진행률 표시, 업로드 완료 알림 (D-18). 5GB를 넘는 파일은 업로드 전에 막고 안내 문구를 보여준다 (D-22). 확장자가 `.mp4` `.avi` `.mkv` `.mov`가 아닌 파일도 업로드 전에 막고, 녹화기의 MP4·AVI 내보내기를 쓰라는 안내를 보여준다 (D-43). 만료·사용 완료된 링크의 안내 문구도 정한다
- 차량 선택·파손 부위 입력 화면 (D-29, 확정). 아래는 입력 방식에서 따라오는 요구사항이고, **화면 구성과 문구는 팀원 1이 U-15에서 정한다**
  - "차량을 드래그해주세요" 안내에 따라 정지 장면 위에서 **본인 차량 자리를 드래그**한다. 그린 사각형이 그대로 차량 영역으로 표시된다. 누끼(차량 외곽) 표시는 우선 하지 않는다 (D-36)
  - 이어서 "파손 부위를 드래그해주세요" 안내에 따라 차량 사각형 위에서 **한 번 더 드래그해 파손 부위**를 그린다. 차량 영역 밖으로 그렸을 때의 안내 문구를 정한다
  - 두 드래그 사이에는 서버를 부르지 않는다. 두 입력을 마친 뒤 한 번에 저장한다 (D-36). 저장 전에 확인 단계를 둘지는 이 화면에서 정한다
  - **[다시 입력]은 1단계가 끝나기 전까지만 보여준다.** 상태 조회(05장 9번)의 `status`가 `stage1_input_done`이면 고칠 수 있고, `stage1_done`이면서 `input_done`이 `true`면 이미 2단계 작업이 들어가 고칠 수 없다 (D-49). 고칠 수 없을 때의 안내 문구를 정한다
  - 다시 입력할 때는 이전에 그린 사각형을 불러오지 않는다. 차량부터 다시 두 번 드래그한다 (D-49)
  - 드래그 좌표는 원본 해상도 기준 픽셀로 보낸다. 화면이 이미지를 축소해 보여주더라도 `naturalWidth`·`naturalHeight`로 되돌려 계산한다 (05장 5.6, 5.7). 파손 부위는 차량 사각형 안(경계 포함)에서만 받는다 — 밖으로 그리면 백엔드가 422로 거절한다 (05장 5.7)
  - 확장: 나중에 누끼를 넣으면 차량 드래그 직후 외곽선 표시와, 맞는 탐지가 없을 때(폴백)의 안내가 더해진다 (D-36 확장 방법 2)
  - 다시 그리기(취소)와, 정지 장면에서 본인 차량을 찾지 못했을 때의 재업로드 안내. **정지 장면은 영상 시작 장면 1장이고 다른 시점으로 넘기는 버튼은 없다** (D-48). 가려졌든 아직 들어오지 않았든 이미 나갔든 안내는 재업로드 하나다 (PRD 3.2). 관리자에게는 **차가 이미 주차된 뒤부터 잘라 달라**고 안내한다 (업로드 화면 문구, U-15)
- 후보 확인 화면: 후보 영상, 후보마다 [찾음], 묶음 아래 [다음] 버튼 하나(= 묶음 전체 "못 찾음"), 남은 후보 수 (D-37). 조회 API는 05장 12번이다
  - **VLM 점수는 화면에 없다.** 배열 순서가 곧 점수순이고, API가 점수를 돌려주지 않는다 (05장 5.8)
  - 후보가 0건이면 후보 확인 화면 자체가 열리지 않는다. 상태가 바로 `exhausted`가 되므로(04장 전이 14) 아래 완료 화면으로 간다 (D-50)
- 완료(더 볼 후보 없음) 화면: `status`가 `exhausted`일 때. **문구는 `candidate_total`로 갈린다** (05장 9번, D-50)
  - `candidate_total > 0` — 사용자가 [다음]으로 전부 넘긴 경우. "모든 후보를 확인했습니다" (PRD 3.6)
  - `candidate_total == 0` — 후보가 애초에 없던 경우. "후보 구간이 탐지되지 않았습니다". **"사건 없음"으로 쓰지 않는다** (PRD 3.5). 재업로드·문의 안내를 둘지 정한다 🚧
  - 클립 안에서 사건 지점이 어디인지 표시할지 정한다. 위치는 `incident_at_sec − start_sec`다 (05장 5.8)
  - [다음] 버튼 이름, 누르기 전 확인창 여부, 다음 묶음을 만드는 동안(`batch_running`)의 대기 안내
  - **원본이 파기됐으면 [다음]을 보여주지 않는다.** 상태 조회(05장 9번)의 `raw_deleted`가 `true`일 때다. 원본이 없으면 다음 묶음의 후보 클립을 만들 수 없다 (D-52)
    - 지금 묶음은 그대로 볼 수 있다. 이미 만들어 둔 마스킹본이기 때문이다. **[찾음]도 그대로 쓸 수 있다** — 고정은 마스킹본 클립을 가리킬 뿐이라 원본이 필요 없다 (D-32)
    - [다음] 자리에 안내문을 둔다. 문구는 여기서 정한다 🚧 (U-15). 뜻은 "보관 기간(3일)이 지나 원본 영상이 파기돼 더 이상 후보를 만들 수 없다"이고, **"분석에 실패했다"로 읽히지 않게 쓴다.** 실패가 아니라 개인정보 보호를 위한 정상 동작이다
    - 화면이 오래돼 버튼이 남아 있는 채로 [다음]을 누르면 409 `RAW_EXPIRED`가 온다. 9번을 다시 불러 안내문으로 바꾼다 (05장 13번)
  - 이전 묶음으로 돌아가 다시 볼 수 있게 할지 🚧
- 사건 지점 고정 화면: 원본 시간 위치 강조, 고정 전 확인. 고정 해제는 두지 않는다 (D-40). 조회 API는 05장 15번이다
  - 원본 기준 시작·끝(`start_sec`·`end_sec`)을 `03:40:35` 같은 형식으로 보여줄지 정한다. API는 초(실수)로 준다 (05장 5.9)
  - 다운로드 버튼을 두지 않는다 (불변 조건 8)
- **보관 기간 종료 화면**: 상태 조회(05장 9번)의 `masked_deleted`가 `true`일 때다. 업로드 완료에서 30일이 지나 마스킹본·분석 결과가 파기된 상태다 (D-57)
  - 정지 장면·후보 확인·사건 지점 화면 **전부** 이 안내로 대체한다. 세 화면의 조회 API(10·12·15번)가 모두 409 `MASKED_EXPIRED`를 준다
  - 문구는 여기서 정한다 🚧 (U-15). 뜻은 "보관 기간(30일)이 지나 영상이 삭제되었다"이고, `RAW_EXPIRED`와 마찬가지로 **"분석에 실패했다"로 읽히지 않게 쓴다**
  - **결과를 볼 수 있는 기간을 미리 알린다.** 기준이 업로드 완료 시각으로 고정이라 날짜를 계산해 보여줄 수 있다. 사건 지점 고정 화면에 "이 결과는 YYYY-MM-DD까지 볼 수 있습니다"를 둔다
- 영상·이미지 재생 공통: presigned URL이 만료돼 S3가 403을 주면 그 화면의 조회 API를 다시 불러 새 URL로 이어 재생한다. 재생 위치는 유지한다 (D-41, 05장 5.1)
- 와이어프레임
- PRD 4장 ⚠️ UX 항목 확정 (키보드 조작 등. 고정 전 확인과 사건 지점 해제 없음은 D-40으로 확정)
