# 09. KPI 평가 설계

> 🚧 일부 작성. 9.1~9.7(평가 데이터·라벨링·표본 수·보고 형식)만 작성했다. 나머지는 "작성할 항목"에 남겨 둔다.

## 작성할 항목

- KPI 3개(비식별화 누락률, 사고 클립 후보 검출 누락률, VLM 정렬 품질)의 평가 스크립트 구조
- 데이터셋 준비, 룰 조정용·최종 측정용 클립 분할
- 추가 라벨(파손 부위 공간좌표, 비충돌 클립의 접근 쪽 면) 형식
- 서비스와 같은 `pipeline` 패키지를 재사용하는 방식

## 관련 결정·조건

- KPI 정의와 측정 방법: PRD 2장 "성공 기준 / KPI"
- KPI 목표값: D-75. 비식별화 목표값·누락 판정: D-88 (제출 5% 이하, 추진 99%, 정답 박스 중심이 가려졌는지로 판정). 비식별화 데이터셋: 🚧 U-29
- 평가 데이터·라벨링·보고 원칙: D-86 / KPI 범위·달성 판정·선택 평가 세트: D-87
- 평가와 서비스가 같은 코드를 쓰는 저장소 구조: [03장 3.3](03-tech-stack.md#33-저장소-구조)

## 9.1 평가 원칙

KPI 수치만 재서 보고하지 않는다. 측정 조건을 미리 고정하고, 수치의 신뢰 범위와 실제 환경과의 차이를 함께 보고한다 (D-86).

- **측정 전에 고정한다**: 조정용·평가용 분할, 임계값, 누락 판정 기준값, 제외 기준. 측정 뒤에 바꾸거나 클립을 빼지 않는다 (PRD 2장).
- **조정과 측정을 나눈다**: 임계값·룰·크롭 크기를 맞춘 데이터로 KPI를 재지 않는다. 같은 데이터로 조정하고 재면 수치가 부풀려진다. 비식별화도 마찬가지다.
- **학습 데이터와 겹치지 않는다**: 비식별화 모델을 파인튜닝하거나 증류할 때 쓴 이미지·영상은 평가에 쓰지 않는다.
- **평가 정답은 사람이 만든다**: 모델이 만든 라벨(의사 라벨)로 평가하면 "그 모델을 얼마나 흉내 냈나"만 잰다 (9.3).

## 9.2 평가 데이터 구성

**공공 데이터셋으로 공식 KPI를 측정한다.** 직접 라벨링한 세트는 선택 사항이며, 만드는 경우 우리 환경 확인용으로 따로 평가한다. 두 결과를 합쳐 한 숫자로 만들지 않는다 (D-87).

| | 공공 데이터셋 (AI Hub, Kaggle) | 직접 라벨링한 세트 🚧 (U-34) |
|---|---|---|
| 역할 | **KPI 공식 수치** | 우리 환경에서도 비슷하게 나오는지 확인 |
| 장점 | 표본이 많다. 제3자가 만든 라벨이라 객관적이다 | 주차장 CCTV 구도, 야간, 한국 번호판에 가깝다 |
| 단점 | 촬영 환경이 우리와 다르다 (9.6) | 표본이 적어 신뢰구간이 넓다 |
| 조정에 쓰나 | 조정용으로 나눈 부분만 | **쓰지 않는다.** 평가 전용이다 |

- 공공 데이터셋 목록은 PRD 2장 KPI 표를 따른다.
- 직접 라벨링한 세트는 만들지 여부, 영상 출처, 규모가 🚧 (U-34)다. 만든다면 규모는 **200~500프레임**을 제안한다 ⚠️. 한 프레임에 1~2분이면 팀원 몇 명이 하루 이틀에 끝낼 수 있다.
- 직접 라벨링한 세트가 작더라도 공공 결과와 **방향이 맞는지**만 확인한다. 크게 다르면 그 차이 자체를 한계로 보고한다.

## 9.3 라벨링 방법

직접 라벨링하는 평가 정답(9.2)과, 원본에 없어 팀이 추가하는 라벨(PRD 2장: 파손 부위 공간좌표, 비충돌 클립의 접근 쪽 면)에 적용한다.

**평가 정답은 처음부터 사람이 그린다**

- 모델이 친 박스를 고쳐서 평가 정답으로 쓰지 않는다. 모델이 놓친 것은 사람도 놓치기 쉬워, 모델에 유리한 정답이 된다.
- 학습용 데이터는 이와 다르다. 학습용은 선생 모델의 의사 라벨을 사람이 검수해서 써도 된다 (U-09의 증류 방식).

**박스 기준을 라벨링 전에 정해 문서로 공유한다**

- 박스를 어디까지 칠지(예: 얼굴은 이마까지인지 머리 전체인지, 번호판은 판만인지 테두리까지인지)를 미리 정한다. 사람마다 다르면 누락 판정이 흔들린다.
- 크기가 작은 대상도 모두 정답에 넣는다 (D-88). 심하게 가려진 대상을 넣을지는 미리 정하고, 뺐다면 뺀 개수를 함께 적는다.

**측정 단위는 파이프라인 전체다**

- 비식별화 누락률은 탐지 모델의 정확도(AP)가 아니다. 타일·크롭·추적 보간·사람 전체 가리기까지 거친 **최종 마스크**가 정답 박스를 가렸는지로 잰다.
- 그래서 평가 스크립트는 서비스와 같은 `pipeline` 패키지로 마스크를 만들고, 정답 박스와 비교한다.

## 9.4 표본 수와 신뢰구간

**KPI 달성 여부는 평가 데이터의 실측값으로 판단한다.** 후보 누락률은 실측 1% 이하, VLM AUC는 실측 0.80 이상을 기준으로 한다. 비식별화는 실측 누락률 5% 이하(얼굴·번호판 합산)를 기준으로 한다. 정답 박스의 중심이 마스크로 가려졌으면 탐지, 가려지지 않았으면 누락이다 (D-88). 보고는 합산 수치로 하고, 얼굴(사람)·번호판 수치는 내부에 따로 기록한다. 신뢰구간은 합격 기준이 아니라 일반화의 불확실성을 보고하는 보조 정보다 (D-87).

누락률은 **95% 신뢰 상한**을 함께 보고한다. 누락이 적게 나와도 표본이 적으면 실제 누락률이 더 높을 수 있기 때문이다.

- 계산: 이항분포의 단측 95% 상한(Clopper-Pearson). 누락이 0개면 대략 `3 ÷ 표본 수`다("3의 법칙").

| 누락 결과 | 단측 95% 신뢰 상한 |
|---|---|
| 0 / 100 | 약 2.9% |
| 1 / 100 | 약 4.7% |
| 2 / 100 | 약 6.2% |
| 0 / 300 | 약 1.0% |
| 1 / 300 | 약 1.6% |

KPI별 해석은 다음과 같다.

| KPI | 가능한 표본 | 해석 |
|---|---|---|
| 사고 클립 후보 검출 누락률 | 평가용 A 클립 약 100개가 전부다 | 실측 누락률 1% 이하이면 평가 데이터 기준 목표 달성이다. 일반화된 누락률의 95% 신뢰 상한까지 1% 이하로 낮추려면 누락 0개로도 약 300개가 필요하다. 따라서 **"누락 k / 평가용 클립 수, 95% 상한 x%"로 보고한다** |
| VLM 정렬 품질 (AUC) | 충돌 약 100개, 비충돌 약 300개 | AUC 0.80 근처에서 95% 신뢰구간이 약 ±0.06이다 (Hanley–McNeil 근사 ⚠️). 신뢰구간을 함께 보고한다 |
| 비식별화 누락률 | 박스 단위라 많이 확보할 수 있다 | 아래 규칙을 따른다 |

**비식별화 표본을 뽑는 규칙**

- 연속 프레임의 같은 얼굴·번호판은 사실상 같은 표본이다. 박스 수만 늘려도 신뢰도가 올라가지 않는다.
- 그래서 **서로 다른 장면을 많이** 넣고, 한 영상에서는 프레임을 **간격을 두고** 뽑는다. 간격은 🚧 (U-29).
- 규모 제안 ⚠️: 공공 데이터셋은 서로 다른 장면 50개 이상, 얼굴(또는 사람) 박스 수천 개, 번호판 박스 1천 개 이상.
- 신뢰 상한은 박스 수로 계산하되, 장면 수를 함께 적는다.

## 9.5 조건별 결과

전체 수치 하나만 보고하지 않고, 우리 CCTV에서 흔한 조건으로 나눠 따로 잰다. 전체 평균이 좋아도 특정 조건에서 무너질 수 있기 때문이다.

- 비식별화: 대상 크기(모델 입력 기준 px 구간), 주간·야간, 가림 여부
- 후보 검출·VLM: 실패한 클립을 유형별로 모은다(가림, 먼 거리, 스치듯 지나감 등)
- 나누는 구간은 측정 전에 정한다. 측정 뒤에 결과가 좋은 구간만 골라 보고하지 않는다.

## 9.6 공공 데이터셋의 환경 차이 다루기

직접 라벨링이 부족하면 공공 데이터셋으로 재되, **"공공 데이터 결과가 우리 환경에서도 같다"고 가정하지 않는다.** 대신 다음 두 가지를 한다.

1. 우리 조건과 비슷한 부분만 골라 따로 잰다 (9.5). 예: "모델 입력 기준 20px 이하 얼굴에서 재현율 X%"
2. 환경 차이와 그 영향을 표로 적는다.

실제 환경에서 더 높은 수치에 도달하도록 테스트와 개선을 계속한다. 환경 차이 표는 다음 개선 방향을 정하는 데도 쓴다.

| 차이 | 결과에 미치는 영향 |
|---|---|
| 카메라 높이·각도 | 얼굴이 보이는 각도가 달라진다. Kaggle RC카 데이터는 카메라 높이 0.8m다 |
| 해상도 | 같은 거리의 얼굴·번호판 크기가 달라진다 |
| fps | AI Hub 사람 데이터는 3fps라 추적 보간의 효과를 제대로 재기 어렵다 |
| 번호판 종류 | Kaggle 번호판 데이터로 대체하면 해외 번호판이다 |
| 클립 길이 | 짧은 단일 사건 클립이라 긴 영상에서의 성능은 검증 범위 밖이다 |
| 크롭 | 서비스는 본인 차량 주변만 크롭해 대상을 키운다 (D-70). 공공 데이터셋에는 본인 차량이 없으므로, 서비스의 크롭 크기와 같은 타일로 나눠 크롭 효과를 재현한다 |

**추진 목표 99%의 검증** (D-88): 공공 데이터셋 결과는 제출 목표 5% 판정에 쓴다. 99%는 주차장과 비슷한 데이터셋에서 따로 잰다. 데이터셋은 조사 후 정한다 🚧 (U-34).

## 9.7 결과 보고 형식

공식 KPI는 비식별화 누락률·사고 클립 후보 검출 누락률·VLM AUC 세 가지다. 사건을 발견한 후보 순위는 평가 항목에서 제외한다 (D-87).

KPI마다 아래 항목을 적는다.

| 항목 | 예시 |
|---|---|
| 결과와 표본 수 | "누락 0 / 104클립" |
| 신뢰구간 | "단측 95% 신뢰 상한 2.8%" |
| 고정한 조건 | 임계값, 분할, 누락 판정 기준값, 제외 기준과 제외한 개수, 측정 날짜, 코드 커밋 |
| 실패 사례 분석 | 놓친 것이 무엇이고 왜 놓쳤는지 (프레임 캡처 포함. 비식별화 실패 캡처는 팀 내부에서만 본다) |
| 조건별 결과 | 9.5의 구간별 수치 |
| 환경 차이와 개선 방향 | 9.6의 환경 차이 표. 더 높은 수치를 위해 계속 테스트·개선한다 |
| 직접 라벨링 세트 결과 | 있으면 공공 결과와 따로 적는다 (9.2) |

## 9.8 필수 평가 범위

VLM 정렬은 필수 기능이며 ROC AUC 평가를 반드시 수행한다. 공식 AI KPI는 비식별화 누락률, 사고 클립 후보 검출 누락률, VLM 정렬 품질의 세 가지다. GPU 시간당 영상 처리량 및 이를 이용한 GPU 대수 산정은 평가 범위에서 제외한다. 후보 클립 10개를 5분 이내에 준비하는 응답 시간 조건은 별도로 유지한다 (SRS REQ-010, D-92).
