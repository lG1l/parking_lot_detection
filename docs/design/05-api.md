# 05. API 명세

> 🚧 미작성. 작성할 항목과 이미 정해진 관련 결정만 적어 둔다.

## 작성할 항목

- 엔드포인트 목록, 요청·응답 예시 JSON, 에러 응답 형식
- 업로드 링크 발급 API: 로그인한 피해자가 호출해 일회용 `token`을 받는다 (D-28)
- 업로드 URL 발급 API: 원본 영역 업로드용 presigned URL을 돌려준다. **로그인 대신 업로드 링크의 `token`으로 인증한다**(D-28). 만료·사용 완료된 토큰은 거절한다. **이 요청이 GPU EC2 켜기 신호다** (D-15, D-18)
- 업로드 완료 알림 API: 브라우저가 업로드를 마친 뒤 호출한다. 백엔드가 1단계 작업을 SQS에 넣는다. 이 요청도 `token`으로 인증한다
- 업로드 방식: 데모는 단일 PUT(최대 5GB). 실제 운영에서 멀티파트로 바꿀 때 추가·변경할 API는 [11장 D-22](11-decisions.md#d-22-업로드는-단일-put으로-구현하고-실제-운영에서는-멀티파트로-바꾼다)의 할 일 목록을 따른다
- GPU 켜기 요청이 거부될 때(꺼지는 중) 재시도 방식 (U-20)
- 분석 상태 조회: "대기 중 (앞에 N건)" 포함. 화면의 조회 주기 (U-18)
- 정지 장면 조회 (5분 이전 이동 포함)
- 본인 차량 선택·파손 부위 입력: 드래그한 사각형을 받아 탐지 결과와 맞춰 차량 영역(누끼)을 확정하고, 파손 부위 사각형이 차량의 어느 쪽인지 계산해 저장한다 (D-29). 1단계 진행 중에도 받는다. 1단계가 이미 끝났으면 2단계 작업을 SQS에 넣고 GPU EC2 켜기를 요청한다 (D-15)
- 후보 묶음 조회, 찾음 / 못 찾음 제출. "못 찾음"이면 다음 묶음 작업을 SQS에 넣고 GPU EC2 켜기를 요청한다
- 사건 지점 고정·해제, 고정된 사건 지점 조회
- 마스킹본 presigned URL 발급 규칙 (유효 시간 등)

## 관련 결정·조건

- 불변 조건 1(원본 재생 URL 미노출), 8(다운로드 기능 없음): [02장 2.4](02-architecture.md#24-이중-경로와-불변-조건)
- 프론트와 API는 같은 출처이며 프론트는 상대경로 `/api/...`로 호출한다: D-11
- API는 분석을 하지 않는다: D-14
- 작업 전달은 SQS, 상태는 DB: D-16
- presigned URL 직접 업로드: D-18 / 단일 PUT과 멀티파트 전환: D-22

- 차량·파손 부위 입력은 두 번 드래그, 방향은 백엔드가 계산: D-29
