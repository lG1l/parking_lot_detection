# 07. 화면 설계

> 🚧 미작성. 작성할 항목과 이미 정해진 관련 결정만 적어 둔다.

> ⚠️ **D-67~D-75 반영 필요 (2026-09-27, 팀장).** 아래 "작성할 항목"은 아직 고치지 않았다. 바뀌어야 할 곳과 영향만 적는다. 팀원 1이 U-15에서 반영한다. 근거는 [11장](11-decisions.md), PRD 3.2·3.5.

## 작성할 항목

- 화면 목록과 화면 전환 (PRD 4장이 설계 문서로 미룬 세부 화면·문구, U-15)
- 화면별 구성요소와 Loading / Empty / Error 상태, 표시 문구
- 에러 문구: API 에러의 `code`별 한국어 문구 (코드 목록은 [05장 5.1](05-api.md#51-공통-규칙), D-38). 409 `INVALID_STATE`는 상태를 다시 조회해 화면을 새로 그린다
- 분석 상태 표시 (상태 목록은 04장, `uploading`·`upload_failed`는 05장 5.5)
  - 업로드 중: 관리자가 올리는 중이다. 이 영상은 아직 열 수 없다 (D-47)
  - 업로드가 확인되지 않음(`upload_failed`): **"실패"로 단정하지 않는다.** "업로드가 확인되지 않습니다 — 큰 파일이면 아직 올라오는 중일 수 있습니다. 한참 지나도 그대로면 관리자에게 확인하고, 중단됐다면 링크를 다시 발급하세요." (D-47)
  - 대기 중 (앞에 N건)
  - 1단계 분석 중 (입력 가능): 1단계가 끝나기 전에도 차량·파손 부위를 입력할 수 있다 (D-15). **입력은 한 번만 받는다** (D-66)
  - 입력 완료·1단계 진행 중, 2단계 분석 중, 확인 가능, 실패
  - GPU EC2를 켜는 중일 때의 대기 안내 (부팅 1~2분)
- 상태 조회 주기 (5~10초, U-18). 너무 자주 묻지 않는다 (D-19)
- 로그인 화면: 회원가입 화면은 없다. 계정은 미리 만들어 둔다 (D-44)
- 업로드 링크 발급 화면 (피해자용): 링크 발급, 유효 시간 안내, 재발급 (D-28). **발급 API는 버튼을 눌렀을 때만 부른다.** 화면을 열거나 새로 고칠 때 자동으로 부르면 이미 관리자에게 보낸 링크가 무효가 된다. 다시 발급하면 이전 링크가 무효가 된다는 것도 버튼 옆에 안내한다 (05장 5.4). 링크는 주차장 관리자에게 보여주는 용도라고 안내한다. 피해자가 원본을 직접 올리는 경로는 없다 (D-45)
- 관리자 업로드 화면: **로그인 없이 링크 주소로 여는 화면**이다 (D-28). 브라우저에서 S3로 직접 업로드, 진행률 표시, 업로드 완료 알림 (D-18). 진행률을 받으려면 업로드 진행 이벤트를 쓸 수 있는 방식으로 보내야 한다(`package:http`의 `put`으로는 진행률이 나오지 않는다). 5GB 파일을 메모리에 통째로 올리지 않도록 파일 객체를 그대로 넘긴다. 같은 진행 이벤트에서 남은 시간을 계산해, GPU 켜기 임계(01장 1.6) 이하가 되면 GPU 켜기(05장 16번)를 **1회** 호출한다. 실패해도 무시한다 (D-62). 5GB를 넘는 파일은 업로드 전에 막고 안내 문구를 보여준다 (D-22). 확장자가 `.mp4` `.avi` `.mkv` `.mov`가 아닌 파일도 업로드 전에 막고, 녹화기의 MP4·AVI 내보내기를 쓰라는 안내를 보여준다 (D-43). 만료·사용 완료된 링크의 안내 문구도 정한다
- 차량 선택·파손 부위 입력 화면 (D-65, D-66). 아래는 입력 방식에서 따라오는 요구사항이고, **화면 구성과 문구는 팀원 1이 U-15에서 정한다**
  - **① 차량 고르기.** 정지 장면 위에 10번 응답의 `detections`를 사각형으로 겹쳐 그리고, "본인 차량을 선택해주세요" 안내에 따라 **하나를 눌러 고른다.** 차량을 드래그하지 않는다 (D-65)
    - 고른 사각형을 다른 색·굵기로 강조하고, 고르기 전에는 다음 단계로 넘어가지 않는다
    - **겹친 사각형 중 어느 것이 잡히는지**를 정해야 한다 🚧. 주차장은 차가 많아 사각형이 겹친다. 누른 점을 품는 사각형이 여럿이면 **작은 것**(= 앞에 있어 덜 가려진 차)을 잡는 쪽이 자연스럽다 — 팀원 1이 정한다 (U-15)
    - 사각형이 많아 화면이 덮이면 선을 얇게 하고 채우기를 없애는 등 표시 방식을 정한다 🚧 (U-15)
  - **② 파손 부위 드래그.** "파손 부위를 드래그해주세요" 안내에 따라 **고른 차량 사각형 안에서** 드래그한다. 차량 영역 밖으로 그렸을 때의 안내 문구를 정한다
  - **③ 확인창.** 저장 전에 확인창을 띄운다. 고른 차량 사각형과 그린 파손 부위를 정지 장면 위에 함께 보여주고, **"저장한 뒤에는 고칠 수 없습니다"** 를 알린다. 취소하면 ①로 돌아간다. 문구는 여기서 정한다 🚧 (D-66, U-15)
  - 고르기와 드래그 사이에는 서버를 부르지 않는다. 확인창에서 [저장]을 눌렀을 때 11번을 한 번 부른다 (D-36, D-66)
  - **[다시 입력] 버튼은 없다.** 저장하면 고칠 수 없다. 상태 조회(05장 9번)의 `input_done`이 `true`면 입력 화면을 열지 않는다 (D-66). 화면이 오래돼 저장 버튼이 남아 있는 채로 눌리면 409 `INVALID_STATE`가 오므로 9번을 다시 부른다
  - 좌표는 원본 해상도 기준 픽셀로 보낸다. 화면이 이미지를 축소해 보여주더라도 `naturalWidth`·`naturalHeight`로 되돌려 계산한다 (05장 5.6, 5.7). 파손 부위는 고른 차량 사각형 안(경계 포함)에서만 받는다 — 밖으로 그리면 백엔드가 422로 거절한다 (05장 5.7)
  - **탐지가 0건이거나 목록에 본인 차가 없으면 재업로드 안내로 간다.** 차량을 드래그하는 폴백은 두지 않는다 (D-65). 아래 "다시 그리기와 재업로드 안내"와 **같은 화면**이므로 새 상태가 아니다 — [내 차가 목록에 없습니다] 버튼을 둘지와 문구만 정한다 🚧 (U-15)
  - 확장: 겹친 차를 픽셀 단위로 가르려면 다각형 외곽선 표시와 다각형 hit-test가 더해진다 🚧 (D-65, U-09)
  - 다시 그리기(취소)와, 정지 장면에서 본인 차량을 찾지 못했을 때의 재업로드 안내. **탐지가 0건이거나 목록에 본인 차가 없는 경우도 이 안내로 보낸다** (D-65). **정지 장면은 영상 시작 장면 1장이고 다른 시점으로 넘기는 버튼은 없다** (D-48). 가려졌든 아직 들어오지 않았든 이미 나갔든 안내는 재업로드 하나다 (PRD 3.2). 관리자에게는 **차가 이미 주차된 뒤부터 잘라 달라**고 안내한다 (업로드 화면 문구, U-15)
- 후보 확인 화면: 후보 영상, 후보마다 [찾음], 묶음 아래 [다음] 버튼 하나(= 묶음 전체 "못 찾음"), 남은 후보 수 (D-37). 조회 API는 05장 12번이다
  - **여러 장면을 고정할 수 있다 (D-80).** [찾음]을 눌러도 화면을 떠나지 않는다. 고정한 후보에는 "확정됨" 표시를 붙이고 그 [찾음]은 막는다. 표시는 14번 응답(= 15번의 고정 목록)의 `candidate_clip_id`로 그린다
  - **고정이 1개 이상이면 [확인 끝내기]를 보인다 (05장 17번).** 누르기 전에 확인창을 띄운다 — 끝내면 더는 [찾음]을 누를 수 없다. 끝내면 결과 화면으로 간다. 고정이 0개면 버튼이 없고, [다음]으로 후보를 넘겨 완료 화면(`exhausted`)으로 끝난다
  - **이전 묶음으로 돌아갈 수 있다 (D-79).** [다음]으로 넘긴 뒤에 이전 묶음에 사건이 있었다는 것을 깨달았을 때 돌아가 [찾음]을 누르기 위해서다
    - 묶음 아래에 [◀ 이전]과 [다음 ▶]을 둔다. "묶음 2 / 3"처럼 지금 보는 묶음과 받은 묶음 수(`latest_batch_no`)를 보여준다
    - 이미 받은 묶음 사이를 옮길 때는 12번에 `?batch_no=N`을 붙여 부른다. 서버 상태는 바뀌지 않는다
    - **마지막 묶음에서만 [다음 ▶]이 [다음 묶음 받기]가 된다** — 이것이 13번(묶음 전체 "못 찾음")이다. 이전 묶음을 보는 중에는 13번을 부르지 않는다
    - **마지막 묶음에서 `remaining`이 `0`이면 [다음 묶음 받기]를 누를 때 확인창을 띄운다.** 넘기면 `exhausted`(끝 상태)가 되어 더는 [찾음]을 누를 수 없다 (D-79, D-80, 05장 13번)
    - 이전 묶음에서도 [찾음]은 그대로 쓴다. 이미 "못 찾음"으로 넘긴 후보라도 고정할 수 있다
    - 다음 묶음을 만드는 동안(`batch_running`)에도 이전 묶음을 보고 [찾음]을 누를 수 있다. 고정해도 만들던 묶음은 그대로 이어진다. 이때 [확인 끝내기]를 누르면 만들던 묶음은 버려진다(04장 전이 15)
  - **VLM 점수는 화면에 없다.** 배열 순서가 곧 점수순이고, API가 점수를 돌려주지 않는다 (05장 5.8)
  - 후보가 0건이면 후보 확인 화면 자체가 열리지 않는다. 상태가 바로 `exhausted`가 되므로(04장 전이 14) 아래 완료 화면으로 간다 (D-50)
- 완료(더 볼 후보 없음) 화면: `status`가 `exhausted`일 때. **문구는 `candidate_total`로 갈린다** (05장 9번, D-50)
  - `candidate_total > 0` — 사용자가 [다음]으로 전부 넘긴 경우. "모든 후보를 확인했습니다" (PRD 3.6).
  - `candidate_total == 0` — 후보가 애초에 없던 경우. "후보 구간이 탐지되지 않았습니다". **"사건 없음"으로 쓰지 않는다** (PRD 3.5). 재업로드·문의 안내를 둘지 정한다 🚧
  - 클립 안에서 사건 지점이 어디인지 표시할지 정한다. 위치는 `incident_at_sec − start_sec`다 (05장 5.8)
  - [다음 묶음 받기] 버튼 이름, 누르기 전 확인창 여부, 다음 묶음을 만드는 동안(`batch_running`)의 대기 안내. 대기 안내는 이전 묶음을 가리지 않게 둔다 (D-79)
- 결과 화면: 고정한 사건 지점 목록을 보여준다. 고정 해제는 두지 않는다 (D-40). 조회 API는 05장 15번이다
  - `finished`일 때, 그리고 `exhausted`인데 고정이 1개 이상일 때 보인다 (D-80). `exhausted`에 고정이 0개면 완료 화면을 보인다
  - 목록의 각 항목은 원본 시간 위치를 강조하고, 누르면 그 클립(`view_clip`)을 재생한다
  - 원본 기준 시작·끝(`start_sec`·`end_sec`)을 `03:40:35` 같은 형식으로 보여줄지 정한다. API는 초(실수)로 준다 (05장 5.9)
  - 다운로드 버튼을 두지 않는다 (불변 조건 8)
- **보관 기간 종료 화면**: 상태 조회(05장 9번)의 `masked_deleted`가 `true`일 때다. 업로드 완료에서 30일이 지나 마스킹본이 전부 파기된 상태다 (D-57)
  - 정지 장면·후보 확인·사건 지점 화면 **전부** 이 안내로 대체한다. 세 화면의 조회 API(10·12·15번)가 모두 409 `MASKED_EXPIRED`를 준다
  - 문구는 여기서 정한다 🚧 (U-15). 뜻은 "보관 기간(30일)이 지나 영상이 삭제되었다"이고, `RAW_EXPIRED`와 마찬가지로 **"분석에 실패했다"로 읽히지 않게 쓴다**
  - **결과를 볼 수 있는 기간을 미리 알린다.** 기준이 업로드 완료 시각으로 고정이라 날짜를 계산해 보여줄 수 있다. 결과 화면에 "이 결과는 YYYY-MM-DD까지 볼 수 있습니다"를 둔다
- 영상·이미지 재생 공통: presigned URL이 만료돼 S3가 403을 주면 그 화면의 조회 API를 다시 불러 새 URL로 이어 재생한다. 재생 위치는 유지한다 (D-41, 05장 5.1)
- 와이어프레임
- PRD 4장 ⚠️ UX 항목 확정 (키보드 조작 등. 고정 전 확인과 사건 지점 해제 없음은 D-40으로 확정)

## 관련 결정·조건

- 완료 알림 대신 화면 상태 표시: D-05
- 차량·파손 부위 입력: D-29 / 우선 누끼 없이 드래그한 사각형을 그대로 표시, 한 번에 저장: D-36
- **본인 차량은 탐지된 차량 중에서 고른다. 파손 부위는 고른 차량 안에서 드래그한다: D-65** (폴백 없음 — 탐지 실패는 재업로드 안내)
- 후보마다 [찾음]만, 묶음 단위 [다음]이 "못 찾음": D-37
- 이전 묶음으로 돌아가 보고 고정할 수 있다(다음 묶음 만드는 중 포함. 끝 상태가 되면 불가): D-79
- 여러 장면 고정, "확정됨" 표시, 고정 1개 이상일 때 [확인 끝내기](`finished`), 결과 화면은 고정 목록: D-80
- 후보 0건이면 `exhausted` + `candidate_total`로 문구 구분: D-50
- 클립을 못 만든 후보는 목록에서 빠진다(화면 변경 없음): D-51
- 마스킹본 파기(업로드 완료 30일) 뒤에는 결과 화면을 안내문으로 대체한다: D-57, `masked_deleted`는 05장 9번 / 원본·트랙·마스킹본은 업로드 완료 30일 뒤 한 번에 파기(끝 상태와 상관없음): D-64, D-80
- 1단계 중 입력 허용, GPU 켜기 대기: D-15
- 재생 URL 만료 시 재조회: D-41
- 업로드 중·업로드 실패 표시: D-47
- 입력 수정은 1단계가 끝나기 전까지, `input_done`으로 판단: D-49 → **입력은 한 번만. 저장 전 확인창, [다시 입력] 없음: D-66**
- 대기 순서 표시, 조회 주기: D-19

# 07. 화면 설계

## 1. 화면 목록과 화면 전환
- **주요 흐름(피해자용)**: 로그인 화면 ➔ 업로드 링크 발급 화면 ➔ 분석 상태 표시(대기) 화면 ➔ 차량·파손 부위 입력 화면 ➔ 후보 확인 화면 ➔ 사건 지점 고정 화면(또는 완료 화면)
- **업로드 흐름(관리자용)**: 업로드 링크 주소로 접속 ➔ 관리자 업로드 화면 ➔ 업로드 완료 알림

## 2. 화면별 세부 명세 및 구성 요소

### 2.1 로그인 화면
- 회원가입 화면은 제공하지 않으며, 사전에 만들어 둔 계정으로 로그인한다 (D-44).

### 2.2 업로드 링크 발급 화면 (피해자용)
- **구성**: 링크 발급 버튼, 발급된 링크 주소, 유효 시간 안내, 재발급 버튼
- **동작**:
  - 발급 API는 버튼을 눌렀을 때만 호출한다 (화면 새로고침 시 무효화 방지).
  - 다시 발급하면 이전 링크가 무효화된다는 것을 버튼 옆에 안내한다 (05장 5.4).
  - 피해자가 원본 영상을 직접 올리는 경로는 없다 (D-45).
- **안내 문구**: "이 링크는 주차장 관리자에게 보여주는 용도입니다."

### 2.3 관리자 업로드 화면
- **구성**: 별도 로그인 없이 피해자가 전달한 링크 주소로 접속하는 화면 (D-28). 파일 선택 버튼, 진행률 표시바, 완료 알림 (D-18).
- **동작**: 브라우저에서 S3로 직접 업로드 수행.
- **에러 및 상태 문구**:
  - 5GB 초과 파일 선택 시 (D-22): "파일 용량이 5GB를 초과하였습니다"
  - 미지원 확장자 선택 시 (D-43): ".mp4, .avi, .mkv, .mov인 확장자만 선택해주세요."
  - 링크 만료/사용 완료 시: "만료되거나 이미 사용이 완료된 링크입니다."
  - 업로드 중 (D-47): "관리자가 영상을 업로드 중이므로 아직 열 수 없습니다."
  - 업로드 실패 (D-47): "업로드가 확인되지 않습니다 — 큰 파일이면 아직 올라오는 중일 수 있습니다. 한참 지나도 그대로면 관리자에게 확인하고, 중단됐다면 링크를 다시 발급하세요."

### 2.4 분석 상태 표시 화면 (공통 대기)
- **동작**: 5~10초 주기로 상태 조회 API를 호출하되, 너무 자주 묻지 않게 처리한다 (D-19, U-18).
- **상태별 안내 문구**:
  - 대기 중: "처리를 대기중입니다. 잠시만 기다려주세요."
  - GPU 부팅 대기: "GPU EC2 서버를 켜는 중입니다. 약 1~2분이 소요됩니다."
  - 1단계 분석 중: 1단계가 끝나기 전에도 즉시 차량·파손 부위 입력이 가능하도록 화면을 열어준다 (D-15, D-67).
  - 입력 완료·1단계 진행 중, 2단계 분석 중, 확인 가능, 실패 상태에 맞는 화면을 각각 노출한다.

### 2.5 차량 선택·파손 부위 입력 화면 (피해자용)
- **구성**: 영상 시작 정지 장면 1장(다른 시점 이동 없음, D-48), 탐지된 차량들의 사각형 겹쳐서 표시, **파손 사진 1장(선택)과 텍스트 설명(선택)** 입력란 추가 (D-72).
- **동작**:
  - **① 차량 고르기**: 탐지 상황이 [보임]일 경우 정지 장면 위 사각형 중 본인 차량 하나를 눌러 고른다. 고른 사각형은 다른 색/굵기로 강조하며, 고르기 전에는 넘어갈 수 없다. 차량을 별도로 드래그하지 않는다 (D-65).
  - **② 파손 부위 드래그**: 고른 차량 사각형 내부에서 드래그하여 파손 부위를 그린다. (탐지 상황이 [안 보임]일 경우 통로 쪽/옆면 등 파손 쪽 위치를 입력하는 권장안 버튼(U-25, U-26) 배치)
  - **③ 확인창**: 고른 차량과 파손 부위, 선택 입력한 사진/텍스트를 함께 보여주며 저장 여부를 확인한다.
  - **저장 처리**: [저장] 시 서버 호출 1회 진행. [다시 입력] 버튼은 제공하지 않는다 (D-66). 상태 조회의 `input_done`이 `true`면 입력 화면을 열지 않는다. 409 `INVALID_STATE` 발생 시 상태를 다시 조회해 화면을 새로 그린다.
- **관련 문구 및 설정**:
  - 파손 부위를 차량 사각형 밖으로 그렸을 때 거절하는 안내 문구: "파손 부위가 차량을 벗어났습니다. 다시 그려주세요."
  - 저장 전 확인창 문구: "저장한 뒤에는 고칠 수 없습니다"

### 2.6 후보 확인 화면
- **구성**: 본인 차량 주변으로 잘라낸 후보 클립 재생, 후보마다 [찾음] 버튼, 남은 후보 수 표시 (D-37). 화면 크기 및 비율 처리가 반영된 비디오 플레이어.
- **동작**:
  - VLM 점수는 화면에 노출하지 않으며 배열 순서대로 보여준다.
  - 묶음 단위 아래에 [다음] 버튼 하나를 두어 전체 "못 찾음"을 처리한다.
- **관련 문구 및 설정**:
  - [다음] 버튼 전 묶음 단위 확인창을 띄울지 여부를 정해서 작성해주세요
  - 다음 묶음을 만드는 동안(batch_running) 보여줄 대기 안내 문구: "다음 영상 묶음을 만드는 중입니다."
  - 🚧 확장 논의: `[이전 묶음으로 돌아가 다시 볼 수 있게 할지 여부를 결정해 작성해주세요]`

### 2.7 완료 및 파기 안내 화면
- **완료 화면 (`exhausted` 상태)**:
  - `candidate_total > 0` (사용자가 전부 넘긴 경우): "모든 후보를 확인했습니다" (PRD 3.6).
  - `candidate_total == 0` (애초에 후보 0건): "후보 구간이 탐지되지 않았습니다" (사건 없음으로 표기 금지, PRD 3.5).
- **원본 영상 파기 시 (`raw_deleted == true`)**:
  - 업로드 30일 경과로 원본이 없어 다음 묶음을 만들 수 없는 경우. 마스킹본은 그대로 조회 및 [찾음] 고정 가능 (D-32, D-52).
  - 다음 버튼 자리를 대체할 문구: "보관 기간(30일)이 지나 원본 영상이 파기돼 더 이상 후보를 만들 수 없습니다." 
- **마스킹본 보관 기간 종료 시 (`masked_deleted == true`)**:
  - 업로드 완료 후 30일 경과. 정지 장면/후보 확인/사건 지점 화면 전부 이 화면으로 대체 (D-57).
  - 안내 문구: "업로드 완료 후 30일이 경과하여 보관 기간이 종료되었습니다."

### 2.8 사건 지점 고정 화면
- **구성**: 원본 시간 위치 강조 표시, 고정 전 확인창 노출. 고정 해제 및 다운로드 버튼은 제공하지 않는다 (D-40).
- **동작**: 사건 확인이 끝나면(pinned 등) 고정한 클립 1개 외에는 파기된다 (D-64).
- **관련 문구 및 설정**:
  - **시각적 표시 방식**: 비식별화된 영상 플레이어 하단 진행바(Progress bar)에 사건 발생 추정 구간(후보 판정 시점 + 5초를 중심으로 한 전후 15초)을 다른 색상(예: 빨간색)으로 하이라이트 처리하여 사용자가 직관적으로 인지할 수 있게 한다.
  - **시간 표시 형식**: 백엔드 API가 제공하는 초(실수) 단위 시간은 사용자 친화적인 시:분:초 형식(예: `03:40:35 ~ 03:41:05`)으로 변환하여, 경찰에게 바로 전달할 수 있는 '원본 영상 기준 시간'으로 화면 중앙에 크게 강조 표시한다.
  - **기한 안내 문구**: 화면 상단에 "이 결과는 YYYY-MM-DD까지 볼 수 있습니다."라는 문구를 띄워, 고정된 클립의 보관 기간(업로드 완료일 기준 30일)을 미리 알린다.

## 3. 공통 에러 및 UX 항목
- **API 에러 메시지 (D-38)**: 백엔드의 에러 응답(`code`)에 따라 화면에 띄울 한국어 스낵바(Snackbar) 또는 모달 안내 문구
  - `INVALID_STATE` (409): "상태가 변경되었습니다. 최신 화면으로 새로고침합니다." (이 문구를 띄우고 상태 조회 API를 다시 호출해 화면을 새로 그린다)
  - `RAW_EXPIRED` (409): "보관 기간(30일)이 지나 원본 영상이 파기되어 더 이상 후보를 만들 수 없습니다."
  - `MASKED_EXPIRED` (409): "보관 기간(30일)이 지나 영상이 안전하게 삭제되었습니다."
  - `VALIDATION_FAILED` (422): "입력값이 올바르지 않습니다. (예: 파손 부위를 차량 영역 안으로 지정했는지 확인해 주세요)"
  - `DEFAULT` (그 외 서버 에러): "일시적인 시스템 오류가 발생했습니다. 잠시 후 다시 시도해 주세요."

- **재생 URL 만료 처리 (D-41)**: presigned URL이 15분 만료되어 S3에서 403 에러가 발생하면, 사용자에게 에러를 띄우지 않고 백그라운드에서 조회 API(10·12·15번)를 다시 불러 새 URL을 발급받아 끊긴 위치부터 이어 재생한다.

- **접근성(UX) 지원 (D-08, PRD 4장)**: Flutter Web의 `Focus`와 `Shortcuts` 위젯을 활용해 마우스 없이 키보드만으로 핵심 조작이 가능하도록 구현한다.
  - **영상 재생 제어**: 영상 플레이어에 포커스가 있을 때 `Spacebar`로 재생/일시정지, `←`/`→` 방향키로 앞/뒤 탐색을 지원한다.
  - **버튼 조작**: 화면 내 주요 버튼(`[찾음]`, `[다 음]`, `[고정 취소]` 등)은 `Tab` 키로 포커스를 이동할 수 있어야 하며, `Enter`나 `Spacebar`를 눌러 클릭 이벤트를 발생시킨다.
- **와이어프레임**:
