## 1. 결론

- 국내외 서비스·연구 **51건**을 조사한 결과, **비식별화 · 후보 구간 선별 · 피해자 본인 확인**을 하나로 묶은 사례는 찾지 못했다.
- 시장은 **"사건 시점을 이미 아는" 쪽**(비식별화 대행·리댁션)과 **"비식별화 없이 권한자가 원본을 보는" 쪽**(VLM 검색·관제·수사지원)으로 갈라져 있고, 그 사이가 이 프로젝트의 자리다.
- 다만 **구성 요소 하나하나는 모두 이미 존재한다.** 기여는 개별 알고리즘이 아니라 세 단계를 한 파이프라인에 배치한 방식에 있다고 설명해야 방어가 된다.

## 5. 질의 형태 비교 — 핵심 차별점의 근거

51건의 "사용자가 무엇을 입력해서 대상을 찾는가"는 **8가지**로 수렴한다.

| 질의 형태 | 해당 유형 |
|---|---|
| 없음 (구간·파일을 사람이 지정) | A, B, C |
| 자연어 문장 | D |
| 객체 속성 / 예시 이미지 | H |
| 이벤트 클래스 선택 | E, F |
| 정상 패턴 이탈 | H (Avigilon UMD) |
| 물리 트리거 (충격 임계값) | G |
| 입출차 전후 비교 | I |
| 시간축 움직임 (차량이 흔들렸는가) | J |
| **공간 좌표 (본인 차량 + 파손 부위)** | **본 프로젝트만** |

긁는 장면은 육안으로도 잘 안 보여서 말로 설명할 수도(D), 사진으로 지목할 수도(H) 없다. 이 프로젝트는 "그 좌표에 뭔가 왔다"는 사실만으로 후보를 만든다.

## 6. 가장 가까운 비교 대상과 예상 반론

| 비교 대상 | 예상 반론 | 준비할 답 |
|---|---|---|
| **BriefCam** (H) | "분량 줄이기는 BriefCam이 이미 한다" (1.5시간 → 14초 사례) | 차이는 압축이 아니라 **거르는 기준**. BriefCam은 움직이는 객체를 전부 겹쳐 사람이 전체를 훑게 하고, 이 프로젝트는 피해자가 지정한 좌표 기준으로 볼 필요 없는 구간을 애초에 뺀다. 비식별화 미확인, 구매자가 수사기관이라는 점도 다름 |
| **위플로 VAIS** (I) | "입출차 비교가 더 간단하지 않나" (시흥 힐스테이트 실증, 손상 데이터 100만 건) | ① 언제 생겼는지만 알 뿐 **가해자를 특정하지 못함** ② **게이트 촬영 설비 필요** — 기존 아파트 지하주차장엔 해당 없음. 경쟁이 아니라 **보완 관계**라고 먼저 말할 것 |
| **JCDE 2024 논문** (J) | "주차장 저강도 뺑소니 찾기는 이미 연구됐다" | 발표에서 **먼저 인용**할 것. 저 논문은 AI가 접촉을 판정하고 연구자가 결과를 본다. 자체 데이터셋 정확도 96.93%가 실제 수집 영상에서 75%(증강 후 83.33%)로 떨어지고, 놓친 순간은 복구할 방법이 없다. 이 프로젝트는 근접을 모아 피해자가 합법적으로 직접 확인한다 |
| **Twelve Labs** (D) | "VLM 영상 검색은 새롭지 않다" (AWS Bedrock에 모델 제공 중) | 차별점은 VLM 자체가 아니라 **앞단의 좌표 기반 후보 선별 + 뒷단의 비식별화 결합**. 동시에 PRD 3.4에서 바로 쓸 수 있는 선택지이기도 함 |

## 7. 우리 서비스의 차별점 (강한 순)

1. **탐지 문제를 검색 문제로 재정의** — 접촉을 판정하지 않고, 접촉이 가능했던 근접을 전부 모아 사람에게 넘긴다. 모델이 틀려도 근접만 남아 있으면 후보군에 남는다.
2. **질의가 공간 좌표** — 51건 중 공간 좌표를 질의로 받는 사례 없음.
3. **분석 경로와 열람 경로 분리** — 비식별 의무는 열람 시점에 걸리므로 원본으로 분석(정확도 손실 없음)하고 마스킹본만 보여준다. 기존은 전부 단일 경로(A·B·C는 전부 마스킹 후 열람, D·F는 원본 분석·열람).
4. **가려진 영역을 인접 관측 영역으로 대리** — 파손 부위가 안 보이면 옆 주차면·통로의 진입·이탈을 신호로 쓴다. 상용 사례 미확인, 논문성 있는 부분.
5. **AI는 판정하지 않고 순서만 정한다** — 오탐은 사용자가 걸러내므로 치명적이지 않음. E군 자동 판정은 놓치면 복구 불가.
6. **"전부 확인했다"가 성립** — 후보군을 소진하면 못 찾더라도 "내가 후보 전부를 봤다"는 상태에 도달. 결과가 아니라 **검증 가능성**을 제공.
7. **비설치형** — 녹화된 영상 파일만 있으면 특수 장비 없는 일반 주차장에도 사후 적용 가능.

## 8. PRD 수정 사항

### 8.1 프로젝트 목적 · 포지셔닝 (PRD 1장)

- **출력물 정의를 명시한다.** 이 서비스의 출력은 "가해자를 찾아주는 것"이 아니라 **"시점을 모르는 긴 CCTV 영상을, 피해자가 합법적으로 직접 전부 확인할 수 있는 분량으로 줄여주는 것"**이다. 현재 목적 문장에는 이 정의가 없다.
- **기여 범위를 인정하고 한정한다.** 비식별화·VLM 검색·객체탐지는 모두 기존 기술이다. 기여는 "비식별화 · 좌표 기반 후보 선별 · 본인 열람을 한 파이프라인에 배치한 것"으로 적는다.
- **명칭에 "탐지"를 쓰지 않는다.** `유사서비스.pdf` 표지는 "개인정보 마스킹 기반 뺑소니 탐지 시스템"으로 적혀 있는데, 이는 차별점 1(탐지 → 검색 재정의)과 충돌한다. PRD 프로젝트명처럼 "후보 구간 선별"로 통일한다.

### 8.2 문제정의 (PRD 1장)

| 항목 | 현재 | 수정 제안 |
|---|---|---|
| 문제 2 (조사 범위 불확실성) | 4개 문제 중 하나 | **핵심 문제로 격상.** 기존 비식별화 서비스(A·B·C군)는 전부 "의뢰인이 구간을 지정한다"는 전제라 시점을 모르면 막힌다. 이 지점이 곧 시장의 공백 |
| 문제 4 (비용) | 피코소프트 단가 1건만 인용 | 시세 데이터 보강 (4장 참고) + **문제 2와 결합한 비용 규모** 추가. 시점을 모르면 전 구간을 비식별화해야 하는데, 3일치(4,320분)를 단순 계산하면 트러스트 모자이크 60분 패키지 기준 약 1,368만 원, 피코소프트 단가(대상 1개) 기준 약 3,888만 원. *실제 견적이 아닌 규모 예시* |
| 문제 3 (신뢰성) | 경찰 조사 결과를 믿기 어렵다 | AI 관제도 "이상 없음"으로 끝나 같은 한계를 가진다는 점 추가. 해결 방향은 "결과"가 아니라 **"검증 가능성"** |
| (신규 전제) | 없음 | 블랙박스(G군)가 전원·각도 한계로 파손 순간을 놓친 경우가 대상이라는 한 줄 추가 — "왜 CCTV인가"에 대한 답 |

### 8.3 핵심 목표 · 핵심 가치 (PRD 2장)

우선순위(비식별화 → 후보 선별 → 정렬)는 유지하되, 각 목표의 **표현을 차별점이 드러나게** 바꾼다.

| 우선순위 | 현재 | 수정 제안 | 이유 |
|---|---|---|---|
| 1 | 합법적인 직접 확인 — 비식별화(모자이크) | **분석은 원본, 열람은 마스킹본 (이중 경로)** | 비식별화 자체는 포화 시장이라 차별점이 아니다. 법적 전제조건으로는 여전히 1순위이고, 차별점은 경로 분리에 있다 |
| 2 | 파손 부위에 근접하는 모든 순간을 후보군으로 선별 | **본인 차량·파손 부위 좌표를 질의로, 재현율(놓치지 않기) 우선 선별.** 파손 부위가 가려진 경우 인접 영역(옆 주차면·통로)으로 대리 | "모든 순간"의 의미를 재현율 목표로 명확히 한다. 차별점 1·2·4가 전부 여기에 걸려 있다 |
| 3 | VLM 정렬 — 부가 기능, 타협 가능 | **AI는 판정하지 않고 순서만 정한다** 원칙 명시 | VLM이 틀려도 후보에서 빠지지 않으므로(정렬만 하므로) 재현율에 영향이 없다. "타협 가능"의 근거가 이 구조 |
| **신규** | — | **검증 가능성: 후보군을 소진하면 "후보 전부를 직접 확인했다"는 상태에 도달한다** | 문제정의 3번(신뢰성)에 직접 대응하는 목표가 현재 없다 (차별점 6) |

핵심 가치 4가지도 같은 방향으로 조정을 제안한다. [결정 필요]

- 현재: 개인정보 보호 · 직접 확인 · 후보 자동 선별 · 가능성 높은 후보순 정렬
- 제안: **개인정보 보호(이중 경로) · 시점 미상 대응(좌표 기반 후보 선별) · 검증 가능한 직접 확인 · 가능성 높은 후보순 정렬**

### 8.4 Scope / Non-Scope (PRD 2장)

**Scope 조정**

- "파손 부위가 CCTV에 보이지 않는 경우의 부분 커버"는 현재 부가 항목처럼 적혀 있다. 상용 사례가 없는 차별점 4이므로 비중을 올린다(3.3 기능 설명과 발표에서 강조).

**Non-Scope 추가**

| 항목 | 이유 |
|---|---|
| 접촉 여부 자동 판정 · 가해자 특정 | AI는 정렬만, 최종 판정은 사용자 (차별점 5). 기능 범위를 오해받지 않도록 명시 |
| 차량 흔들림(시간축 움직임) 기반 접촉 탐지 — JCDE 2024 방식 | 실제 수집 영상 정확도 75~83%, 놓친 순간 복구 불가. 경쟁지형도 PDF는 이 문구가 PRD에 이미 있다고 인용했지만 **현재 PRD에는 없다** → 추가 필요 |
| 실시간 관제 · 사전 설치형 운영 | 녹화된 영상 파일의 사후 분석만 다룬다 (차별점 7, E군과 구분) |
| 입출차 외관 비교(VAIS 방식) | 보완 관계로 두고 이번 범위에서 제외 |

### 8.5 성공 기준 / KPI (PRD 2장, 현재 미작성)

조사 결과로 보면 이 서비스의 가치는 "놓치지 않기"와 "볼 수 있는 분량"에 달려 있다. 아래 지표를 제안한다. 목표 수치는 [결정 필요].

| 지표 | 정의 | 연결된 목표 |
|---|---|---|
| **후보 재현율** (최우선) | 실제 접촉 순간이 후보군에 포함되는 비율 | 우선순위 2, 차별점 1·5 |
| 확인 분량 축소율 | 원본 영상 길이 대비 사용자가 보는 후보 구간 총 길이 | 출력물 정의, 3.5의 n·t |
| 정렬 품질 | 정답 구간이 상위 n개 안에 드는 비율 / 정답 구간의 평균 순위 | 우선순위 3 |
| 비식별화 누락률 | 열람 경로 영상에서 마스킹이 누락된 번호판·사람 비율 | 우선순위 1 |

참고 비교 기준: 선행연구(JCDE 2024)는 실제 수집 영상 정확도 75%(증강 후 83.33%).

### 8.6 주요 기능별 (PRD 3장)

| 섹션 | 수정 제안 |
|---|---|
| 3.1 비식별화 | "사용자에게 보여줄 때만 모자이크 처리"가 지금은 구현 방식처럼 적혀 있다. **이중 경로 설계 원칙**으로 다시 서술한다. 설계 선례로 딥핑소스(사람은 식별 불가·AI는 분석 가능한 익명화)를 인용할 수 있다 |
| 3.1 PbD 인증 | "추후 실서비스화 시 진행"을 구체화할 근거 추가: 연 단위 공모(2026년은 6월 22일 마감), 인증 수수료 전액 지원, 2026년부터 업무용 솔루션까지 대상 확대 |
| 3.3 후보 선별 | 룰 설계 기준을 **재현율 우선**(임계값을 넓게)으로 명시. 질의가 "공간 좌표"라는 점을 기능 설명에 적는다 |
| 3.4 VLM 정렬 | Twelve Labs(Bedrock 제공)를 모델 선택지로 검토. 단, 차별점은 VLM이 아니라 앞뒤 결합에 둔다 |
| 3.5 n, t 값 | n·t는 **"사용자가 감당할 수 있는 분량"을 정하는 설계 결정**이다. 예시: 3일치 4,320분 → n=20, t=10초면 6.7분(약 645분의 1). 확인 분량 축소율 KPI와 함께 정한다 |
| 3.6 / User Flow | PRD의 [질문 필요] "후보를 모두 확인하고도 못 찾은 경우의 흐름"에 대해, **"후보 전부 확인 완료" 상태를 사용자에게 명시적으로 보여주는 방향**을 제안한다 (검증 가능성 목표) |
